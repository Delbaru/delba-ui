# @delba/ui: работа агента

## Режим работы

Выбирай глубину по задаче: **FAST** — известная локальная правка текста,
без проекта целиком; **FOCUSED** — изменение поведения/нескольких компонентов,
точные источники и адресная проверка; **DEEP** — публичный контракт, большой
рефакторинг или миграция потребителей с полноценной приёмкой.
В checkout Diamonds4You управляющий навык — корневой `agent-workflow`;
здесь эти правила самодостаточны и в отдельном клоне.
Не создавай план, индекс, субагентов и полный suite для FAST; повышай режим
только при обнаруженной зависимости или риске. CI/release остаются обязательными.

Самостоятельный репозиторий общей UI-библиотеки. Продуктовые роли, словари и тема
принадлежат потребителю. [README](README.md) — интеграция, [Library](docs/Library.md) —
карта справочника, [development](docs/development.md) — договор разработки.

## Выбор навыков

По цели задачи открывай нужный навык, без ожидания отдельной команды.
Не загружай его расширенные references без относящейся к ним причины.
Для изменения поведения, структуры или API прочитай [принципы](docs/specs/architecture/principles.md)
и нужную тему по [карте спецификаций](docs/specs/README.md).
Очевидная замена текста FAST не требует чтения всех этих документов. Новый или меняющийся договор
фиксируй по её правилам; проверяй критерии по [приёмке](docs/specs/verification/acceptance.md).
При использовании или изменении публичного компонента найди его отдельную страницу
в [каталоге](docs/specs/ui/components/README.md). Новый экспорт сопровождай страницей,
изменение договора — обновлением примера и критериев, без ожидания напоминания.
Для задачи на стыке проектов сочетай навыки владельцев: сайт использует публичный
API, изменение общей механики выполняется по инструкциям DelbaUI. Не обновляй
закреплённую версию у потребителя автоматически.

| Задача                                                           | Навык                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------- |
| Компонент, проп, SCSS, ядро; ревью или рефакторинг этих областей | [ui-component](.agents/skills/ui-component/SKILL.md)     |
| Анимация, переход, отмена, collapse, parallax, perspective       | [ui-motion](.agents/skills/ui-motion/SKILL.md)           |
| Медленный скролл, тяжёлые кадры, память, лишний рендер           | [ui-performance](.agents/skills/ui-performance/SKILL.md) |
| Проверка или завершение изменения                                | [ui-verify](.agents/skills/ui-verify/SKILL.md)           |

Если навык не появился в клиенте, прочитай `SKILL.md` напрямую. Специальные
команды Claude не обязательны. Читать весь журнал уроков не требуется: ищи по симптому.

## Границы

- Имена раскрывают назначение; последовательные действия читаются отдельными
  шагами на всех уровнях — от компонента до внутренних обработчиков и утилит.
  Компактность не достигается плотными однострочниками. Общее поведение
  имеет одного владельца, а композиция остаётся видимой у потребителя; новая
  обёртка должна давать понятный договор, а не просто прятать существующий вызов.
- В проектах Delba публичные D-компоненты в `src/shared/ui` и `src/cms/ui` имеют
  папку `DName/` с `DName.tsx`, `DName.config.ts`, `DName.skin.ts`,
  `DName.module.scss` и `index.ts`. Это форма проектных компонентов; она не
  применяется к примитивам DelbaUI, ядру, внутренним частям или helper-папкам.
  Потребитель с `componentAnatomy: 'single-config'` объединяет sizes/skins/presets/
  states в `DName.config.ts` и не имеет `DName.skin.ts`; проверка строго требует
  остальные четыре файла и запрещает split skin. Существующий resolver остаётся один.

- Импортов наружу репозитория нет; потребителю доступны только exports пакета.
- Общие layout/motion/refs и SCSS-миксины берутся из ядра. Цвета и времена — токены.
- Строгий TS, публичные пропсы с JSDoc; responsive нормализуется через ядро.
- Покой — `ui.components`, пропы — `ui.utilities`, состояния — `ui.states`.
- Новый API следует [authoring §3.1](docs/authoring.md): один владелец состояния,
  стабильный DOM ref, композиция событий, SSR, доступность и reduced motion.
- Публичное изменение проверяется на потребителях. Ломающий договор требует миграции;
  отсутствие вызовов в одном потребителе не доказывает, что компонент можно удалить.
- Ревью и рефакторинг сохраняют поведение, exports и сценарии пользователей.
  Коммиты, публикация и обновление потребителей выполняются по заданию.

Для диагностики **изменения поведения UI** предпочитай доступный Chrome DevTools MCP,
для повторяемых сценариев — Playwright. Проверяй настоящий ввод и наблюдаемое
состояние, снимок и скриншот когда они подтверждают изменённое поведение;
FAST-правка текста не требует обхода всех экранов. Производительность — замером до/после.
Инструмент выбирается из доступных в текущем клиенте; правила MCP не подключают.
Особенности Reveal, scroll roots, portals и motion — в
[browser guide](docs/browser-verification.md); общий порядок QA — shared `delba-browser`.

Команды проверки — в ui-verify и package.json. Инструменты документации:
После клонирования или добавления навыка создай локальные ссылки Claude:
`node tools/agent-docs.mjs sync .`; проверка — `node tools/agent-docs.mjs check .`.
Shared links подтверждаются installer manifest `~/.delba/state/toolkit/install.json`;
при нестандартной установке задай `DELBA_TOOLKIT_MANIFEST` с путём к её manifest.
Проверка сверяет источник и действительную установленную ссылку; имя `delba-*`
само по себе не разрешает внешний target. Локальный навык сохраняет приоритет.
Контракты обновляй в docs, устойчивые ошибки в lessons, непроверенное называй явно.
Разовые отчёты, аудиты, скриншоты приёмки и логи в репозитории не сохраняй;
результаты сообщай в чате. В файлах остаются документация, roadmap, навыки и правила.
Аудиты выполняй по отдельной необходимости, а не после каждой правки.
