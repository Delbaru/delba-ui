# @delba/ui: работа агента

Самостоятельный репозиторий общей UI-библиотеки. Продуктовые роли, словари и тема
принадлежат потребителю. [README](README.md) — интеграция, [Library](docs/Library.md) —
карта справочника, [development](docs/development.md) — договор разработки.

## Выбор навыков

По цели задачи прочитай нужный файл до изменения. Навыки можно сочетать.

| Задача | Навык |
|---|---|
| Компонент, проп, SCSS, ядро; ревью или рефакторинг этих областей | [ui-component](.agents/skills/ui-component/SKILL.md) |
| Анимация, переход, отмена, collapse, parallax, perspective | [ui-motion](.agents/skills/ui-motion/SKILL.md) |
| Медленный скролл, тяжёлые кадры, память, лишний рендер | [ui-performance](.agents/skills/ui-performance/SKILL.md) |
| Проверка или завершение изменения | [ui-verify](.agents/skills/ui-verify/SKILL.md) |

Если навык не появился в клиенте, прочитай `SKILL.md` напрямую. Специальные
команды Claude не обязательны. Читать весь журнал уроков не требуется: ищи по симптому.

## Границы

- Импортов наружу репозитория нет; потребителю доступны только exports пакета.
- Общие layout/motion/refs и SCSS-миксины берутся из ядра. Цвета и времена — токены.
- Строгий TS, публичные пропсы с JSDoc; responsive нормализуется через ядро.
- Покой — `ui.components`, пропы — `ui.utilities`, состояния — `ui.states`.
- Новый API следует [authoring §3.1](docs/authoring.md): один владелец состояния,
  стабильный DOM ref, композиция событий, SSR, доступность и reduced motion.
- Публичное изменение проверяется на потребителях. Ломающий договор требует миграции;
  отсутствие вызовов в одном потребителе не доказывает, что компонент можно удалить.
- Ревью и рефакторинг сохраняют поведение, exports и сценарии пользователей.
  Коммиты, публикация и обновление потребителей выполняются по заданию.

Для браузерной диагностики предпочитай доступный Chrome DevTools MCP, для
повторяемых сценариев — Playwright. Используй настоящий ввод и наблюдаемое состояние,
снимок доступности и скриншот; производительность подтверждай замером до/после.
Инструмент выбирается из доступных в текущем клиенте; правила MCP не подключают.

Команды проверки — в ui-verify и package.json. Инструменты документации:
После клонирования или добавления навыка создай локальные ссылки Claude:
`node tools/agent-docs.mjs sync .`; проверка — `node tools/agent-docs.mjs check .`.
Контракты обновляй в docs, устойчивые ошибки в lessons, непроверенное называй явно.
Разовые отчёты, аудиты, скриншоты приёмки и логи в репозитории не сохраняй;
результаты сообщай в чате. В файлах остаются документация, roadmap, навыки и правила.
Аудиты выполняй по отдельной необходимости, а не после каждой правки.
