# Компоненты Frontend

Прочитай [архитектуру](../../../docs/architecture.md) и
[структуру компонента](../../../docs/development.md#публичный-компонент).
Уточни публичные props и актуальный DOM по [каталогу](../../../docs/components.md)
и исходникам. Общий workflow и согласование — [AGENTS.md](../../../AGENTS.md).

1. Назови владельцев состояния, ref и DOM. Сохрани видимую JSX-композицию и
   существующие публичные вызовы, обработчики и клавиатурное поведение.
   Оставь JSX-композицию на виду, правила контрола собери в его модели,
   общие refs, события, popup и scopes бери из Element.
2. Примени props и пресеты для поддержанных свойств. Остаток SCSS размести под
   локальным корнем по реальному дереву. Портал оформляется через API его владельца.
   Runtime CSS принадлежит модулю компонента, глобальное оформление платформы —
   ядру. Сохрани пять файлов из договора структуры, допускаются пустые.
3. Пройди изменённый проп до DOM. Для общего поведения используй feature-вход
   из [архитектуры](../../../docs/architecture.md#публичные-механизмы).
   Импорты сверяй по [границам](../../../docs/architecture.md#границы-импорта).
   Обнови запись каталога при изменении публичного API.
   Темы, токены и адаптивность принадлежат [конфигу](../../../docs/configuration.md).
4. Выбери разрешённую приёмку по [ui-verify](../ui-verify/SKILL.md).

Сначала проверь композицию готовых примитивов. Section использует Flex as="section",
а не новый native host с повторным Element/Motion. Нативный узел оправдан у базового
примитива и платформенного владельца; короткая модель сама по себе не делает
дублирующую реализацию общей.
