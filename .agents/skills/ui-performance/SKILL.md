# Производительность UI-кита

Пути — от корня UI-репозитория. Прочитай [ui-component](../ui-component/SKILL.md),
[core](../../../docs/core.md) и реализацию компонента/хука с его тестами.
Эталон замера — экран потребителя, на котором видна проблема.

1. Зафиксируй сборку, viewport, CPU/network/cache и действие; запиши исходные данные.
   Предпочитай доступный Chrome DevTools MCP trace; Playwright воспроизводит жест.
   Не считай скорость dev/HMR скоростью production.
2. Найди причину в trace: JS, render, forced layout, style/paint/composite, ожидание ресурса.
   Для React проверь область и частоту рендера; memo/useCallback вводи по этой причине.
3. Проверь частоту read/write в кадре, количество observers, остановку rAF,
   visibility/reduced motion, cleanup и удерживаемые узлы после unmount.
   Сохрани договор ref/event, SSR и результат эффекта; не удаляй движение ради цифры.
4. Исправь у общего владельца. Проектную композицию/палитру не переносишь в библиотеку.
   Для motion следуй [ui-motion](../ui-motion/SKILL.md).
5. Повтори тот же сценарий несколько раз в тех же условиях; сравни измерения
   и проверь regression через [ui-verify](../ui-verify/SKILL.md).

Итог различает измеренное улучшение, гипотезу и границы оборудования/покрытия.

Частая работа: причина → решение.

- Layout после записей стилей: один снимок scrollY для подписчиков; кэш rect/диапазона
  с инвалидацией по узлу/размеру/скроллу. ResizeObserver обновляет только зависимые кэши;
  локальный resize не перемеряет документ. Явная команда учитывает DOM до доставки observer.
- Style у потомков: внутренние motion-переменные делай локальными (`@property`, inherits:false),
  сохраняя наследование токенов темы. Проверяй реальное движение и область пересчёта.
- Лишний DOM/React: прежний текст/значение повторно не записывай; изменение состояния
  ограничивай затронутым поддеревом. Memo помогает только со стабильными пропами.
- Покадровый JS-параллакс: для прямой связи со скроллом используй браузерный timeline
  с fallback, сохраняя reveal/наклон, SSR, reduced motion и cleanup.

Фиксируй нагрузку системы/прогрев; rAF cadence не равен FPS вывода. Повторяй тот же жест.
Нет доступного trace/потребителя — назови ограничение; unit-тест не измеряет плавность.
