# Авторинг компонента

Как добавить компонент или проп так, чтобы он не развалил три проекта. Грабли — в
[`lessons/authoring.md`](lessons/authoring.md).

---

## 1. Прежде чем писать — инвентарь

Спроси по порядку и ответь вслух:

1. **Это точно библиотека?** Здесь живёт форма и поведение, а не продукт. Имя по роли
   (`TabTrack`, `SharedBox` в проекте), никогда по бизнесу (`QuestionCard`, `ExamButton`).
   Бизнес-существительное в имени — компонент остаётся в проекте.
2. **Нет ли этого в ядре?** Открой [`core.md`](core.md). Брейкпоинт, «меньше движения»,
   длительность движения, `clamp`, склейка классов, коробка, миксины — уже написаны.
3. **Хватит ли существующего компонента с новым пропом?** Новый проп дешевле нового компонента
   и не плодит близнецов.
4. **Что даст проект?** Если нужен новый токен — он идёт в договор темы
   (`theme/tokens.default.scss`), иначе у потребителя молча пропадёт цвет.

## 2. Структура папки

`Text.letterSpacing` принимает числовой rpx и CSS-длину (`'-0.03em'`, `'normal'`);
интервал относительно шрифта не переносится в SCSS из-за ограничения числового типа.
Проверка ритма допускает толщину 1–2 у размеров линии; padding/gap остаются кратными 4.

`Modal.layout` задаёт геометрию панели (`default` / `fullWidth`). Прежний `preset`
сохранён как совместимый alias; `layout` имеет приоритет. Готовые проектные роли окон
принадлежат компонентам потребителя и объединяют геометрию, оформление и поведение.

```
TabTrack/
  TabTrack.tsx           компонент
  TabTrack.module.scss   стили (только если это крупный виджет; примитиву — глобальные ui-*)
  types.ts               публичные типы, если их больше пары
  index.ts               что видно снаружи
```

Экспорт наружу — через `index.ts` папки и строку в корневом [`src/index.ts`](../src/index.ts).
Путь импорта у потребителя не должен зависеть от того, как файлы разложены внутри.

В большом компоненте выделяй части с собственной ролью, а не каждый короткий JSX-фрагмент.
Например, `InputActions.tsx` отвечает за действия поля, `InputFeedback.tsx` — за показ ошибок,
`types.ts` — за публичные пропсы. Input связывает их со значением и нативным ref; части получают
нужные параметры и callbacks, без копии модели поля или отдельного контекста ради сокращения файла.

## 3. TSX

- **Пропы раскладки не изобретаются.** Коробка (отступы, размеры, радиусы, рамка, фон, `grow`)
  приходит из `src/core/layout/box.ts`: `splitBoxLayout` отделяет её от DOM-пропов, `boxLayout`
  отдаёт классы. Подмножество выражается типом (`Pick`/`Omit<BoxLayoutProps, …>`), а не копией.
  Поля используют этот же `splitBoxLayout`: `const { box, rest: fieldProps } = splitBoxLayout(props)`.
  Оформление собирается через `resolveFieldLayout({ ...box, variant, size, color, placeholderColor })`
  и `fieldLayoutClasses`. Явная геометрия отменяет размер-пресет по умолчанию; явно заданный `size`
  сохраняется. `grow` применяется к обёртке отдельно через `box.grow`.
- **Респонсив-проп** — `ResponsiveValue<T>`; помощники ядра принимают `ResponsiveInput<T>`.
  Проект может включить строгий режим (`UiRules.strictTuple`), и тогда скаляр у него не соберётся —
  поэтому внутри библиотеки нормализуй через `resolveResponsive`, а не через `Array.isArray`.
- **`ref` — обычный проп** (`WithRef<…>`), `forwardRef` не используем. Склейка — `useMergedRefs`.
  У поля подключай `fieldRef` из `useFieldControl` к самому контролу во всех ветках рендера.
  DOM-узел не передаётся через одноразовый `useImperativeHandle(..., [])`; при композиции
  сохраняй функцию очистки callback-ref React 19. Устройство — [`core.md`](core.md).
- **Состояние узла** — атрибут `state` и селектор `&[state~='open']`, а не класс-модификатор:
  состояний на узле бывает несколько сразу.
- **JSDoc у каждого публичного пропа.** Это единственная документация, которую увидит вызывающий.

### 3.1. Единый договор API

Это правила для новых возможностей и изменений API. Таблица указывает существующие
реализации; она не означает, что все компоненты уже прошли проверку поведения.

| Область | Договор | Пример / существующая реализация |
|---|---|---|
| Настройки | Связанные настройки собираются в именованный объект. Одно простое значение остаётся простым; не вводим объект только ради одинакового синтаксиса. | `collapse={{ open, gap: [8, 8, 8], fade: true }}`, но `tooltip="Сохранить"`. Общий тип — [`CollapseOptions`](../src/components/Collapse/CollapseWrap.tsx). |
| Появление | Общий `animate` описывает эффект и момент запуска. `when: 'inView'` — вход в экран; `when: 'load'` — первый кадр через CSS. Старый `reveal` совместим; явный object animate имеет приоритет. | `animate={{ effect: 'up', when: 'inView', delay: 'veryFast' }}`. Имена и секунды задаёт `ui.config.motion.timing`, типы выводит `UiMotionTiming` из ключей конфига (см. README). Используется общий observer; content/swap-эффекты компонентов сохраняются. |
| Части аккордеона | Содержимое и оформление кнопки находятся в `trigger`. ARIA и переключение принадлежат аккордеону. | `trigger={{ content: <Text>Вопрос</Text>, p: [16, 16, 16] }}`. Объект имеет приоритет над legacy `triggerProps`; классы объединяются. |
| Корень и части | Корневой проп относится ко всему компоненту; настройка внутри объекта части — только к этой части. Детали согласования отступов остаются внутри составного компонента. | `collapse={{ open: showButton }}` — кнопка; `icon={{ name: 'arrow-right', collapse: { open: showIcon } }}` — иконка проектного `DButtonIcon`, в том числе без подписи. |
| Состояние | Управляемое значение имеет одного владельца. Не копируем `open` или `value` в независимое внутреннее состояние. Внутренняя фаза анимации может отличаться от целевого состояния. | `collapse={{ open: form.failed }}`; [`useCollapseMotion`](../src/hooks/useCollapseMotion.ts) ведёт переход, а не решает, когда показать ошибку. |
| Начальное значение | `defaultValue` / `defaultOpen` означают начальное значение неуправляемого режима. Не смешиваем начальное и управляемое значения. | `collapse={{ defaultOpen: false, ref: panel }}`; совместное `open` и `defaultOpen` запрещено типами. |
| DOM ref | Обычный `ref` сохраняет назначение, объявленное публичным типом, при включении tooltip, collapse и других возможностей. У поля это сам input/textarea, а не оболочка. | `<Input ref={inputRef} />`; [`useFieldControl`](../src/core/useFieldControl.ts), [`useMergedRefs`](../src/core/useMergedRefs.ts), `WithRef` из ядра. |
| Ref поведения | Отдельная ручка поведения не подменяет DOM ref. Документируем только реально поддерживаемые команды и результаты. | `CollapseControls` даёт `show() / hide() / toggle()` с результатом `finished / interrupted`, `open` и текущий `transition`. Прежний `CollapseHandle` остаётся типом доступа к переходу. |
| Отменяемое действие | Сначала вызываем пользовательский обработчик. Если он сделал `event.preventDefault()`, внутреннее отменяемое действие не выполняем. | [`composeDropdownTriggerClick`](../src/components/Dropdown/trigger.ts) сохраняет `onClick` и позволяет отменить открытие списка. |
| Уведомления | Внутренний и пользовательский callbacks должны вызываться вместе. `preventDefault()` не отменяет обязательную очистку ресурсов или завершение жизненного цикла. | Композиция `onAnimationEnd` при `Flex transitionKey`; для нового поведения нужен сценарий с пользовательским callback. |
| События поля | `onChange` и `onBlur` получают настоящее событие нативного поля. `onValueChange(value, { reason, event })` сообщает значение модели; `event` может быть `null` у программного действия. | Для масок обработчик модели — `onValueChange`, а сырой ввод — `onChange`. Перенос маски из прежнего `onChange` — **BREAKING migration**: перевести чтение нормализованного значения на `onValueChange`. |
| Части поля | `Input.slots.start/end` добавляют содержимое по краям строки; ref и нативные события остаются на input. `collapse` сворачивает всё поле вместе с подписью и подсказками. | `PhoneField` использует `start` для выбора страны и принимает `country={{ countries: ['RU', 'KZ'], default: 'RU' }}` либо `countries: 'all'`; `locale="ru"` задаёт локализованные имена, группированные по коду. |
| Select | Один выбор имеет значение `T | null`, `multiple` — `T[]`. Select владеет выбором и клавиатурной навигацией, Dropdown — панелью; `name` и `form` связывают выбор с нативной формой. | Один выбор отправляет запись, несколько — повторяющиеся записи одного `name`; `form` нужен, когда поле расположено вне DOM формы. |
| Dropdown | Настройки панели находятся в `panel`; `open` и `onOpenChange` задают управляемый режим, `defaultOpen` — неуправляемый. Корневой `className` оформляет корень, `panel.className` — содержимое панели. | `panel={{ side: 'end', offset: 12, portal: true }}`. Раскрытие через общий CollapseWrap; позиционирование и закрытие через общие хуки. |
| Движение содержимого | `Box` и `Flex` принимают `animate` с входом или `[вход, { key }]` для смены. У `Flex` старые `animation` и `transitionKey` сохранены как совместимые пропы; если задан `animate`, они не читаются. | Общая механика — `useContentMotion`; она сохраняет узел и фокус при смене ключа и учитывает reduced motion. |
| Tooltip | Повторно используй общий `useTooltip`/`Tooltip`, а не копию позиционирования и видимости. Не размонтируй якорь при смене текста; сохраняй потребительский `aria-describedby`. | `Button` и `Icon` объединяют id подсказки с переданным описанием и сохраняют стабильный DOM якоря. |
| SSR и доступность | Первые клиентская и серверная разметки согласованы. Закрытые контролы недоступны для ввода; размонтирование убирает слушатели. Reduced motion сохраняет результат и завершение сценария. | [`CollapseWrap`](../src/components/Collapse/CollapseWrap.tsx), общий движок движения в [`core.md`](core.md). Поиск по `hidden="until-found"` — отдельный режим, требующий проверки в браузере. |
| Совместимость | Новая запись не отменяет прежнюю без миграции. Значения по умолчанию и конфликты форм явно описаны. | У `Flex` настройки внутри объекта `collapse` имеют приоритет над прежними отдельными пропами. |

**BREAKING: переход Dropdown на объект панели.** Корневые `side`, `offset`, `portal` удалены;
перенести их в `panel`. Прежний `className` панели теперь задаётся как `panel.className`.
В управляемом режиме обязательны `open` и `onOpenChange`, `defaultOpen` с ними несовместим.
`offset` остаётся в дизайн-единицах. `panel.matchTriggerWidth` измеряет сам триггер,
`panel.inheritVariables` переносит выбранные CSS-переменные оформления в портал.
`side` выравнивает оформленную поверхность относительно триггера даже при растянутом корне.
Портал ограничен viewport с отступами floating hook; явный minW дочернего содержимого
нужно согласовать с matchTriggerWidth, иначе ограничения вызывающего кода конфликтуют.

```tsx
<Dropdown
  open={open}
  onOpenChange={setOpen}
  trigger={<Button>Разделы</Button>}
  panel={{ side: 'end', offset: 12, className: styles.menu }}
>{items}</Dropdown>
```

Составной компонент строится из готовых примитивов и поведения кита. Select не копирует
DOM-оболочки, outside-dismiss, портал и анимацию Dropdown. Нативный элемент остаётся там,
где он нужен по назначению: например, скрытый input для FormData.

**Прежняя совместимая запись Flex:**

```tsx
<Flex
  collapse={open}
  collapseFade
  collapseKeepMounted
  onCollapseFound={reveal}
>{children}</Flex>
```

**Единый объект, как уже сделано в `Accordion`:**

```tsx
<Flex
  collapse={{
    open,
    fade: true,
    keepMounted: true,
    onFound: reveal,
  }}
>{children}</Flex>
```

Для короткого содержимого не нужен отдельный слой раскладки ради подключения поведения:

```tsx
<Text
  role="alert"
  collapse={{ open: !!form.errors.radio, gap: [8, 8, 8], fade: true }}
>{form.errors.radio}</Text>
```

Одно поле раскрывается без дополнительного Flex:

```tsx
const panel = useRef<CollapseControls>(null);
const input = useRef<HTMLInputElement>(null);

async function showField() {
  const result = await panel.current?.show();
  if (result?.status === 'finished') input.current?.focus();
}

<Input ref={input} label="ФИО" collapse={{ defaultOpen: false, ref: panel }} />
```

Команда завершается после перехода и обновления DOM. Новая противоположная команда,
`transition.cancel()` и размонтирование дают `interrupted`; повторная команда того же
направления ждёт уже запрошенный результат. В управляемом режиме команды вызывают
`onOpenChange`; владелец принимает запрос через `open`. Без callback или при отказе владельца
команда даёт `interrupted`, а собственное состояние вместо управляемого не заводится.

Небольшой составной контрол использует готовые части поля; `onValueChange` здесь — канал модели,
а `onChange` при необходимости оставляет доступ к реальному событию input:

```tsx
<Input
    name="email"
    type="email"
    slots={{
        start: <Button type="button" aria-label="Префикс">@</Button>,
        end: <Button type="button">Очистить</Button>,
    }}
    onChange={(event) => auditRawInput(event.currentTarget.value)}
    onValueChange={(value, { reason, event }) => updateEmail(value, reason, event)}
/>
```

У иконковой кнопки состояние слота и состояние всей кнопки не объединяются: `icon.collapse.open`
скрывает только глиф, даже если подписи нет; `DButtonIcon.collapse.open` скрывает кнопку целиком.
При переходе с прежнего поведения «без подписи свернуть кнопку» проверьте экран: оставшаяся кнопка
может быть пустой, поэтому вызывающий код должен управлять корневым `collapse`, если нужен весь контрол.

Для `Input type="tel"` с прежним `phone` значение маски теперь читают из `onValueChange`;
`onChange` получает текст нативного поля и не подменяет `event.target.value`. При переходе на
`PhoneField` передают allowlist стран и начальную страну в `country`, а модель получают как
международный номер.
Без выбора страны используют публичный `Input type="tel"` с `phone`: постоянный
префикс и национальная маска остаются в компоненте. `phone.sample` допускает
заполнители `__________`; длина ввода определяется `digits`, а не видом подсказки.
Контролируемое поле сохраняет позицию каретки и выделения при перемещении разделителей.

Перед добавлением возможности выбираем её владельца из таблицы и проверяем, нет ли общей
реализации в [`core.md`](core.md). JSX-тег оставляем в одной строке, если он помещается в
`printWidth` из корневого `.prettierrc` (140 колонок); длинный открывающий тег переносим по
одному пропу на строку с отступом 4 пробела. Короткое выражение-значение оставляем рядом с
открывающим и закрывающим тегами, если оно помещается в ту же ширину. Поведение подключаем
только там, где есть сценарий, а не автоматически ко всем компонентам.

**Что обеспечивается кодом.** TypeScript проверяет `CollapseOptions` и responsive-кортежи
при `UiRules.strictTuple`. Архитектурная проверка запрещает прямое подключение движка в
модулях компонентов (§6), проверка границ — импорты за пределы библиотеки. Смысл слота,
назначение ref, порядок callbacks и доступность доказываются сценариями поведения и ревью;
успешная проверка типов сама по себе их не подтверждает. Общий запуск — `npm run ui:test --silent`.

AST-правило `jsx-format` проверяет компактные короткие JSX-теги и переносы длинных пропсов.
Оно использует `printWidth` из ближайшего `.prettierrc` (по умолчанию 100) и отступ 4 пробела;
комментарии, сложные дочерние узлы и значимые пробелы не переписываются.
В runtime кита правило строгое, у потребителя старые места учитываются базовой линией.
`npm run ui:test --silent -- --fix` форматирует JSX кита и проекта перед проверкой типов
и тестами. Обычный запуск только проверяет. Примеры `.typecheck` / `.type-test` остаются для tsc.

## 4. SCSS

- **Покой компонента — в `@layer ui.components`**, состояния — в `@layer ui.states`. Порядок
  слоёв объявлен в проекте; правило состояния, написанное в покое, проигрывает утилите пропа.
- **Повторяющийся рецепт — миксин из `src/core/_mixins.scss`** (`reduced-motion`, `truncate`,
  `line-clamp`, `fill`, `hidden-control`, скроллбар). Не нашёл нужного — добавь туда, а не копируй.
- **Только непропсовое**: `position`, `overflow`, `transform`, `transition`, `z-index`,
  `pointer-events`, `opacity`, `display`, `filter`, псевдоэлементы, селекторы состояний.
  Отступ, размер, радиус, фон и зазор задаются ПРОПОМ на вызове.
- **`@media` ради размера — ошибка**: это кортеж. Медиазапрос законен для `prefers-reduced-motion`,
  `hover: none`, ориентации и подобного — и берётся миксином или `MEDIA_QUERY`.
- **Слои перекрытия — токенами `--z-*`** (`--z-modal`, `--z-toast`, `--z-tour`,
  `--z-under-floating`, `--z-floating`, `--z-top`). Голое число остаётся только там, где речь о
  порядке двух соседних узлов внутри компонента.
- **Отступ между блоками потока — только `:not(:last-child)`**, иначе одиночный блок (заголовок
  секции из форматированного поля) несёт лишний низ, и проект перебивает кит из виджета.
- **Ритм, который проекты хотят разный, — переменная с запасным значением**, а не зашитый токен:
  `var(--rich-text-gap, var(--s-8))` в `RichText`. В договор темы такая переменная не входит,
  без неё всё как было, а проект задаёт её одной строкой в теме.

## 5. Классы

Примитивы (`Flex`, `Grid`, `Text` с анимациями, `Icon`, `Img`, `Button`, `Section`)
носят глобальные короткие классы `ui-*` из `src/core/tokens.global.scss`: хеш CSS-модуля на каждом
узле весил в разметке больше самих стилей. CSS-модуль оставляют крупному виджету.

Классы утилит (`p_8`, `n_p_0`, `w_100%`, `bg_--primary`) печатает генератор
[`tools/utilities`](../tools/utilities) под значения, которые он НАШЁЛ в коде проекта. Значение,
существующее только в рантайме (измеренная высота), класса не получит — такому место в `style`.

## 6. Движение

Общий объект `animate` отвечает и за момент, и за эффект:
`{ when: 'inView', effect: 'counter', duration: 'slow' }` у Text,
`{ when: 'change', effect: 'textSlide', duration: 'fast' }` у Text,
`{ when: 'change', effect: 'veil', direction: 1, duration: 'slow' }` у Img.
Hover transform задаётся `{ when: 'hover', effect: 'transform', source: 'closest', scale: 1.025, duration: 'slow' }`;
область карточки отмечается `Flex motionScope`. Hover можно вложить в объект появления.
Открытие Dropdown задаётся `panel.animate={{ when: 'open', effect: 'down', duration: 'normal' }}`;
Select передаёт `panel.animate`, `panel.collapse`, `panel.offset` и `panel.r` той же панели:
проектная обёртка задаёт движение и радиус списка, не копируя состояние и обработчики Dropdown.
подложка, dismiss и ожидание exit принадлежат Dropdown, а не проектным слушателям/таймерам.
У Icon смена глифа задаётся `{ when: 'change', effect: 'swap', duration: 'fast', scale: 1, rotate: 0 }`;
duration относится к каждой из двух последовательных фаз, прежние string/tuple формы совместимы.
В объектных и tuple-формах время — секунды или ключ `ui.config.motion.timing`; legacy counter
мигрирует с миллисекунд на секунды (2500 → 2.5). CSS и JS читают один токен на одном узле
через `motionTimeCss` / `readMotionTimeMs`, а не отдельный список имён или таймер с копией значения.
Умолчания эффектов принадлежат `motion.defaults`, все параметры прокрутки — `motion.scroll`.
Генератор переносит проектные значения в CSS/runtime; внутренние fallback кита нужны
для standalone bootstrap, а не для spread в проектном конфиге. Easing —
`motionEasing` с общей CSS/JS кривой. Observer margins называют top/right/bottom/left явно;
проценты сохраняют width-relative договор IntersectionObserver. Lenis в ките отсутствует.
Прямой ребёнок с `data-reveal-skip` исключён из родительского каскада и его индексов;
собственная анимация ребёнка остаётся. Маркер подходит декоративным слоям, не всей aria-hidden разметке.

- Проверка «пользователь просит меньше движения» — `prefersReducedMotion()` из ядра или миксин
  `m.reduced-motion` в SCSS. Своей копии запроса быть не должно.
- Длительность узла — `readMotionMs(node, 'transition' | 'animation')`.
- Страховочный таймер — расчётная длительность плюс `MOTION_END_BUFFER_MS`. Своё число означает,
  что где-то таймер сработает раньше события и оборвёт анимацию.
- Появление и сворачивание — `usePresence` и `useSwapTransition`, а не рукописный `opacity` +
  `visibility` в модуле.
- Когда нужно скрывать компонент целиком, подключай общий `CollapseWrap` и публичный
  `collapse={{ open, gap, fade, axis }}`. Внутри кнопки используй inline-вариант со `span`;
  внешний `gap` кнопки не анимируется, поэтому зазор исчезающей иконки задавай через `collapse.gap`.
  Это устройство должен скрывать составной компонент кнопки: его вызывающий передаёт только
  наличие иконки, а не вручную согласует два `gap`.
- В `src/components` не импортируй и не реэкспортируй `animateCollapse` напрямую: подключай `CollapseWrap`.
  Низкоуровневый движок остаётся в ядре и общих хуках. Проверка понимает именованные и namespace
  импорты, alias, реэкспорты, `export *`, динамические импорты и деструктуризацию. Type-only
  обращения разрешены. Самописную копию алгоритма AST-правило доказать не может — её ловит ревью.
  Команда из корня проекта — `npm run ui:test --silent`. Тот же запуск проверяет DOM ref:
  одноразовый `useImperativeHandle(...current, [])` для поля заменяется `useMergedRefs`.
- Смысл `collapse` определяется местом в API: корневой проп скрывает весь компонент, проп внутри
  объекта части — только эту часть. Например, `Button collapse={{ open }}` скрывает кнопку, а
  проектный `DButtonIcon icon={{ name, collapse: { open } }}` — её иконку. Не назначай корневому
  `collapse` в одном компоненте другое значение ради компактной записи.
- Продвинутые настройки сворачивания у `Flex` держи в том же объекте:
  `collapse={{ open, keepMounted: true, onFound: reveal }}`. Отдельные `collapseKeepMounted`,
  `onCollapseFound` и другие прежние пропы сохранены для совместимости. Настройка в объекте
  имеет приоритет, если указаны обе формы.

## 7. Совместимость

Единый `delba-ui test` запускает тесты кита и найденные `.test.ts/tsx/js` в `src` проекта.
Проектные тесты выполняются из его корня с тем же репортёром; отдельные команды не нужны.

Добавлять можно почти всё, ломать — почти ничего. Перед правкой существующего пропа спроси:
«что будет у проекта, который обновится завтра?» Если ответ «вид поменяется» — это `BREAKING:`,
и в коммите должно быть написано, как перейти.

## Анимация — проп компонента, а не обёртка

Следующие короткие формы — совместимость прежнего API. Новые вызовы используют
объект `animate={{ when, effect, ... }}` по §3.1 и §6; старые примеры не задают
предпочтительную форму нового публичного договора.

Смена картинки, иконки, текста включается пропом самого примитива (`Img animate`, `Icon animate`,
`Text animation`) в одной форме: ключ, `[ключ]` или `[ключ, опции]`. Логика живёт папкой внутри
компонента (`Img/swap`, `Icon/swap`, `Text/animations`). Отдельный компонент-обёртка (был `Crossfade`)
заставлял проект держать все кадры списком и заворачивать картинку — владелец счёл это неверным
устройством, и его убрали через день после появления.

## Формы — `name` участвует в `FormData`

`Checkbox` и `Radio` принимают `indicator={false}`: скрывается только декоративный
индикатор, нативный input, label, ref и клавиатура сохраняются. Потребитель оформляет
фокус такого варианта сам. Контролируемый Radio отражает checked в `state="active"`,
aria-invalid в error; декор не следует скрывать селектором `input + div`, затрагивающим
соседнее содержимое.

У кастомных полей задавай `name`, чтобы выбранное значение было доступно через нативную форму.
`Select` с одним выбором отправляет одну запись. `Select multiple` отправляет повторяющиеся записи
с одним именем (`formData.getAll(name)`); пустой выбор ничего не отправляет. Отключённый `Select`
не участвует в отправке. Обязательность остаётся поведением компонента: `required` включает его
проверку и семантику доступности, но не заменяет атрибут `required` у нативного `<select>`.

`ChoiceButtons` принимает те же `name`, `disabled` и `required`. Значение сериализует встроенный
`Select`, поэтому оно не дублируется между адаптивными представлениями.

### Отслеживание взаимодействия поверхности

У Flex есть opt-in trackInteraction: он дополняет state токеном interacting для указателя,
фокуса и открытых дочерних Modal/Dropdown, включая порталы и вложенные области. Это факт
взаимодействия, а не команда скрытия; оформление state выбирает потребитель. Отдельный DOM
не создаётся. Для fixed/sticky-элемента с top=0 зона возврата у края viewport сохраняется,
даже если элемент сдвинут вверх. При необходимости onInteractionChange сообщает boolean.
Проектные состояния вроде compact/hide не принадлежат ядру. React useState/useEffect и if
не заменяются отдельной системой команд только ради более короткой записи.


### Независимые эффекты кнопки и документ Lexical

Список Lexical поддерживает `marker: 'dash' | 'disc'` и `markerColor` (CSS-токен
темы). Рендер восстанавливает `disc`/`decimal` после reset, уважает `start` у `ol`;
цвет `::marker` берёт из документа, отдельно от цвета текста. Старые списки без
этих полей сохраняют обычные маркеры. Проект не окрашивает маркеры селекторами секции.

Button принимает появление вместе с независимыми настройками:
`animate={{ when: 'inView', effect: 'up', hover: { effect: 'rise', fill: 'var(--primary)' }, idle: { effect: 'glow' } }}`.
Прежние `when: 'hover'/'idle'` совместимы. У проектной D-кнопки появление сохраняет эффекты роли;
явный hover/idle заменяет её motion, `hover: false` отключает hover поверх появления. Все эффекты
остаются на том же DOM-узле и сохраняют общие ref/events/reduced motion.

LexicalText.content — HTML-строка или публичный `LexicalDocument` с `root.children: unknown[]`.
Редактор/CMS владеет тегом, ролью, marks и цветом. Renderer проверяет каждый узел; повреждённый
узел пропускает, корректных соседей сохраняет. Зависимости библиотеки от CMS нет.

Декларативный `Modal` сохраняет React-контексты места объявления, включая вложенные
провайдеры и их обновления. Реестр хранит порядок и lifecycle, а портал содержимого
рендерится из исходного поддерева. Императивный `present(node)` по-прежнему рендерит
переданный узел в контексте ModalProvider.

`Input.field` и `Textarea.field` принимают `className`/`style` нативного контрола;
`className`/`style` корня относятся к компоненту целиком. DOM ref и события остаются
нативными. `Input.nativeValidation` включает нативный `required` для потребителей,
которые сохраняют браузерную валидацию формы; по умолчанию обязательность проверяет кит.
