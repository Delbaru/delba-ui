# Компоненты, типы и пропы

### Scoped perspective не теряет ввод до первого ответа observer

Visibility observer сначала сообщает false. Scoped pointermove/focus отбрасывали
ввод до асинхронного ответа IntersectionObserver; затем true запускал кадр с нулевой
целью, и единственный hover оставался без результата. Обработчики сохраняют цель,
а существующий scheduler по-прежнему не исполняет движение до visible=true.
Browser regression задерживает настоящий IO callback до после реального hover:
до исправления rotation остаётся 0 и тест падает, после — проходит с прежним >1.
Он также проверяет повтор после замены div→section, отсутствие движения при pending
visibility, игнорирование событий отсоединённого узла и focus после обратной замены.

### Смена доступности и controlled-источника завершает старое действие

Проверка только начала действия пропускала последующие переходы: у disabled
password оставалась фокусируемая reveal-иконка, открытый Select переживал loading,
а старый FileReader MediaDropDown вызывал callback после внешней смены выбора.
InputActions учитывает disabled (readonly по-прежнему допускает reveal), Select
закрывает список при loading без валидации, MediaDropDown отменяет старую операцию
через существующего MediaOperationOwner при изменении controlled value/selectedItem.
Причина и переходы подтверждены SSR и mounted hooks. SSR-регрессия находится в
Input/tests/render.test.ts; сценарии loading и двух controlled media replacements
добавлены в tools/browser/tests/regressions.spec.ts. Эти три browser-сценария прошли
на реальном fixture; полный browser gate остаётся отдельным обязательным этапом.

TabTrack наблюдал только размеры: reorder одинаковых вкладок с прежним value
не меняет размеры и оставлял бегунок на старой позиции. Его владелец измерений
наблюдает также структуру и state, заново находит active и переключает size observer
при замене узла. Style и собственные data-атрибуты не наблюдаются. Mounted-проверка
подтверждает новый offset и сохранение DOM выбранной вкладки; browser regression
`TabTrack follows a keyed tab reorder` прошёл на реальной геометрии без remount.

### Один адрес ресурса для StaticRequire, оптимизации и source identity

Art direction имеет каскад, а не независимые полосы: удаление mobile A в `[A, A, B]`
заставляло телефон брать tablet B через его media below. Подготовка сохраняет mobile A,
когда он перекрывает отличный tablet; `null` продолжает наследовать tablet.
Шесть комбинаций источников проверяются через pure preparation и настоящий SSR;
`Img art direction retains explicit mobile` сверяет currentSrc на mobile/tablet/desktop.

Браузерная проверка обнаружила дополнительную ошибку: SVG data URL с пробелами
принимается в `img.src`, но единственный URL в `source.srcset` разбивается на
дескрипторы. При совпадающем tablet media браузер молча оставлял desktop.
Подтверждено реальным Chromium на SSR Img: media=true, srcset правильного кадра,
currentSrc прежний. Подготовка кодирует ASCII-пробелы только fallback `result.src`;
готовый Next srcSet с несколькими кандидатами и дескрипторами не перекодируется.
Регрессия проверяет pure/SSR fallback и сохранность Next width descriptors;
браузерный currentSrc сверяет фактический выбор ресурса.

Img принимал Next-импорт `{ default: { src, width, height } }`, но разрешал адрес
только у строки и обычного static image. Размеры при этом читались корректно.
В результате такой импорт терял lightbox/source identity, а приватный `/api/`
мог попадать в оптимизатор. `Img.resource.ts` разрешает адрес один раз для всех
трёх решений; `Img.resource.test.ts` проверяет реальный импорт, private policy,
явное переопределение и SSR lightbox.

Готовность изображения также должна отвергать поздний `load` старого слоя:
сравнение с актуальным identity выполняется до изменения состояния blur.
Сценарий `Img object change animate` посылает старое событие после готовности
нового кадра и проверяет, что blur остаётся скрытым.

### Явная граница ошибки внешнего редактора

**Симптом.** Проверка потребителя `tsc --noEmit --incremental false` сообщает
TS7006 у `LexicalComposer.initialConfig.onError`: параметр `nextError` не получил тип.

**Проверенный договор.** Установленный `LexicalComposer.d.ts` объявляет
`onError(error: Error, editor: LexicalEditor): void`. Для обработчика, который
повторно бросает ошибку, достаточно `nextError: Error`; runtime не меняется.
Причина отсутствия контекстного вывода в конкретном окружении не установлена.

**Повторная проверка.** Проверяй строгие типы реального потребителя после правки;
не подменяй границу `any` и не объявляй конфликт peer-зависимостей установленной
причиной без отдельного воспроизведения.

Правила авторинга — [`../authoring.md`](../authoring.md). Здесь то, на чём уже обожглись.

### Код, написанный в проекте, в библиотеке проходит СТРОЖЕ

`TabTrack` приехал сюда из проекта готовым и дал девять ошибок «возможно `undefined`»: у
библиотеки свой `tsconfig.json` с `noUncheckedIndexedAccess`, и `const [a, b, c] = Array.from(...)`
там даёт `T | undefined`, хотя в проекте это молчало.

**Правило: перенос компонента в библиотеку — это не копирование файлов, а прохождение строгого
режима.** Лечится проверкой, а не `!`: у узла и правда может не оказаться детей, если разметку
поменяют. Одна строка `if (!start || !body || !end) return;` честнее восклицательного знака.

### `null` в кортеже значит «пропустить», и чужой код мог писать его в другом смысле

До 15.09.2026 у `grow` и `aspectRatio` `null` НАСЛЕДОВАЛ desktop (значение уезжало инлайн-переменной
с запасным значением). Правило выровняли: теперь `null` — пропуск у любого пропа, «как на desktop»
пишут значением.

**Ловушка при переносе чужого кода:** `grow={[1, null, null]}`, написанное под старым правилом,
означало «растягивается везде», а под новым — «растягивается только на десктопе». При слиянии
такие места нужно читать по смыслу и ставить `[1, 1, 1]`, а не переносить буквально.

### `cx` — склейка КЛАССОВ, а не любых строк через пробел

Кодмод заменил все `[a, b].filter(Boolean).join(' ')` на `cx(a, b)` и споткнулся там, где
склеивались не классы: `state` типа `ComponentStateValue`, идентификаторы для `aria-describedby`
и значения `transform`. Типы это поймали.

**Правило: `cx` ставится там, где результат уезжает в `className`.** Одинаковая форма выражения —
не повод считать смысл одинаковым.

### Проп «на будущее» держит живым целый хук

`perspective3d` и `parallax` объявлены у `SharedMotionProps` и проброшены через `Flex`, `Box`,
`Grid`, `Container`, `Modal`. Передаёт их снаружи НИКТО — ни один из трёх проектов, — но ради них
`useSharedMotion` зовётся на каждом рендере каждого `Flex`, а за ними живут 852 строки хуков.

**Правило: проп заводится под вызывающего, а не под замысел.** Если вызывающего нет — место такому
в ветке или в Roadmap, а не в публичном типе.

### Кодмод, меняющий форму значения, обязан различать проп и ОПЦИИ

Скрипт, который дописывал кортежи, утроил и объекты опций анимаций: `mode: 'swap'` превратился в

**Правило: перед кодмодом выпиши, ЧТО он менять не должен, и проверь это на одном файле глазами.**

### Плавный уход всплывашки держится опцией позиционирования, а не transition'ом

У `.ui-icon-tooltip` были прописаны `transition` на `opacity`, `visibility` и `transform`, и всё
равно при уводе курсора подсказка ПРОПАДАЛА кадром. Причина не в стилях: `IconTooltipWithPortal`
звал `useAnchoredFloating` без `keepPositionWhenInactive`, и на деактивации хук уводил узел на
`-9999px` — уходить было уже нечему. Соседний `useTooltip` эту опцию передаёт, поэтому у одних
всплывашек уход был плавным, а у других нет.

**Правило: у исчезающего портального узла проверяй ДВЕ вещи — доигрывает ли он transition и
остаётся ли он на месте, пока доигрывает.** Симптом «появляется плавно, исчезает мгновенно» почти
всегда второе.

⚠️ **Рецидив 18.09.2026 — календарь поля даты.** Звал `useAnchoredFloating` без той же опции и на
закрытии уезжал за экран в тот же кадр, что и гас. Пользователь: «открывается хорошо, закрывается не
плавно». Замер после правки: прозрачность 1 → 0.58 → 0.10 → 0.02 за ~250 мс на прежнем месте.

### Вложенный слой в СВОЁМ портале по DOM снаружи панели — «клик вне» закрывал хозяина

Календарь поля даты внутри поповера (период в шапке таблицы проекта): первый же клик в календаре —
по месяцу, по дню — закрывал и поповер, и календарь. `useOutsideDismiss` проверял `contains` по DOM,
а портал календаря лежит в `body` рядом с порталом поповера, не внутри.

Лечение — считать «внутри» по дереву React: события через порталы идут по нему. Хук отдаёт
`{ onMouseDownCapture }`, корень панели вешает его и отмечает нативное событие как внутреннее; захват
на корне React случается раньше, чем всплытие дойдёт до слушателя на `document`. Escape — по тому же
правилу слоёв: слой, погасивший клавишу, зовёт `preventDefault`, и внешний по ней уже не закрывается
(так же живёт `Select`). Поле даты при этом забирает Escape ТОЛЬКО с открытым календарём — иначе
закрытое поле запирало бы клавишу и поповер вокруг перестал бы закрываться вовсе.

**Правило: у любой панели, внутри которой бывает поле с собственным плавающим слоем, проверь клик
ВНУТРИ вложенного слоя и Escape по одному разу на слой.**

### Масштаб «пружинки» вешают на СОДЕРЖИМОЕ всплывашки, а не на неё саму

Коробку всплывашки меряет `useAnchoredFloating` (`getBoundingClientRect`), чтобы отцентрировать её
по якорю. `transform: scale(.96)` на самой коробке уменьшил бы измеренную ширину, и подсказка
встала бы мимо центра на пару пикселей. Трансформ ПОТОМКА на раскладку родителя не влияет и на
замер не попадает — поэтому пружинка живёт в `> *`.

### Сворачивание по ширине сжимало содержимое вместе с треком

Симптом: у `Flex collapse collapseAxis='column'` на середине хода подписи переносились по словам
(«Добави / учеников»), а у кнопок с высотой из оси вторая строка вылезала наружу. Проекты лечили это
классом `width: max-content` на каждом вызове — и забывали, рецидивов было три.

Причина: `.ui-collapse-inner` — блочный контейнер, и ребёнок тянулся за шириной трека. В покое этого
не видно: обёртка стоит на `flex-shrink: 0`, то есть и так на ширине содержимого.

**Лечение в примитиве: по ширине внутренний клип — флекс-ряд, ребёнок `flex: none`.** Ребёнок стоит
на своём max-content, трек его только обрезает. Правило живёт в `ui.components`, поэтому явные
`w`/`grow` с места вызова (слой утилит) его перебивают. Проверка — не глазами: поставить обёртке
`grid-template-columns: 0.5fr` без transition и сравнить ширину ребёнка с покоем.

### `hidden="until-found"`: React пишет его булевым, а `inert` и свой `display` его ломают

Режим `collapseKeepMounted` (держать закрытый блок в DOM ради поисковиков и Ctrl+F) упёрся в три
вещи, каждая из которых молча отключает находку:

- **React 19 знает `hidden` только как булев атрибут:** `hidden="until-found"` уходит в DOM как
  `hidden=""`, то есть «спрятать совсем». Значение ставит `useLayoutEffect` через `setAttribute`, а
  React-проп `hidden` в этом режиме всегда пустой, чтобы две стороны не спорили за атрибут.
- **`inert` выключает поиск по странице** (Chrome исключает инертные узлы из find-in-page). Закрытый
  `.ui-collapse` раньше всегда был `inert`; спрятанному `until-found` он не нужен — фокус и дерево
  доступности отрезает `content-visibility: hidden`, который браузер вешает сам.
- **Запасной булев `hidden` (браузер без `until-found`) перебивается `display: grid`** обёртки: стили
  автора сильнее UA-правила `[hidden] { display: none }`. Нужно явное
  `.ui-collapse[hidden]:not([hidden='until-found']) { display: none }`.

И четвёртое, про время: `beforematch` приходит, браузер снимает `hidden` и **сразу** прокручивает к
совпадению. Состояние владельца до двойного кадра `usePresence` не доедет, и прокрутка ушла бы к
нулевой высоте, — поэтому обработчик сам ставит `data-open` + `data-instant` (без transition) в DOM.

**Проверка:** находка — навигацией на `#:~:text=<слово>` (тот же `beforematch`, что у Ctrl+F).
⚠️ В headless-вкладке Playwright `requestAnimationFrame` троттлится до кадра в секунду: раскрытие через
presence «застревает» на пару секунд. Это среда, а не код, — ждать дольше, а не чинить.

### Рендер Lexical молчит на незнакомом узле — и текст из редактора исчезает с сайта

Редактор Delba CMS пишет абзацы и заголовки своими узлами `rich-paragraph` / `rich-heading`:
это абзац плюс визуальная роль («Крупный», «Подзаголовок»), развязанная с тегом. Рендер библиотеки
знал только `paragraph` / `heading`, а в конце `renderNode` стоит `return null` — и всё, что
человек набирал в админке, на сайте выходило пустым местом. Без ошибки, без предупреждения. Так же
пропадал мягкий перенос (`linebreak`, Shift+Enter): соседние куски текста слипались.

Не ловилось долго по одной причине: CMS держала СВОЮ копию библиотеки, и в копии рендер эти узлы
знал. Комментарий в редакторе честно писал «рендерер понимает rich-\*» — про копию. А тексты на
стенде писали скрипты обычным `paragraph`, и ловушка ждала первого сохранения руками.

Лечение — узлы и роли здесь (`RichText/roles.ts`). Роль ставит класс ТОЛЬКО блоку, у которого она
задана в данных: блок без роли красит вариант текста, как и раньше. Подставь рендер роль «по тегу»,
как делала копия, — и каждый абзац на сайте получил бы `--font-p` поверх выбранного варианта.
Классы ролей — в слое `ui.utilities`: в слое покоя `.RichText.default p` (0,2,1) бил бы их (0,1,0).

**Правило: формат данных, который пишет чужой редактор, проверяется на рендере библиотеки, а не
на копии рядом с редактором. Незнакомый узел — это потеря текста, а не «ничего страшного».**

Редактору кит отдаёт то же, чем рисует сайт: `richTextClasses` (классы модуля — корень `RichText` и
роли) и `resolveRole` (какую роль блок показывает на полосе — для панели «Стиль»). Превью устройства —
атрибут `data-device="mobile" | "tablet"` на узле с классом `RichText`: роли полосы
(`role-m-*` / `role-t-*`) включаются без медиазапроса, при любой ширине окна. Правила превью — только
НОВЫЕ селекторы под атрибутом, в том же `ui.utilities` и тяжелее (0,3,0): корень без атрибута не
совпадает ни с одним из них, сайт не меняется ни на пиксель. Шкалу шрифтов устройства (`--rpx`,
`--font-*` мобилки) превью не подменяет — это тема проекта, а не кит.

**Роль — вариант типографики проекта (2026-09-23).** Словарь `RICH_ROLES` (`title`, `dop`…) — набор
кита, а у проекта свой (`typography` в `ui.config.ts`: у «Сердец» `h1`–`h3`, `p1`–`p5`). Роль, которой
нет в словаре, рендер молча выбрасывал: человек выбирал стиль сайта, а на сайте блок оставался за
вариантом текста. Теперь роль вне `RICH_ROLES` — имя варианта, и рендер вешает утилиты генератора
`text_<роль>` / `m_text_<роль>` / `t_text_<роль>` (`textVariantClasses`): генератор печатает их для
каждого варианта на каждой полосе, таблиц соответствия нет. Роли прежнего словаря — классами модуля,
как раньше. Правило имени — одно, `isTextVariantName`: его же зовёт редактор CMS, решая, что хранить.
Блок со СМЕШАННЫМИ ролями (`role: 'h3'` из прежнего словаря, `roleM: 'p1'` — вариант проекта; у
«Сердец» `h1`–`h3` совпадают по имени с прежними ролями) идёт утилитами ЦЕЛИКОМ: `.role-h3` модуля и
`m_text_p1` утилит одной специфичности, и на мобилке победил бы тот файл стилей, что загружен позже.

## Синхронный кэш в первом рендере ломает гидрацию отложенных секций

`useFetchedSvg` брал разобранный SVG из кэша в `useState(() => …)`. Сервер кэша не видит, а секция
под `<Suspense>` гидрируется после того, как иконка уже загрузилась в другом месте: клиент рисует
содержимое, сервер отдал пустое, React не патчит `dangerouslySetInnerHTML` — пустой `<svg>` навсегда.
Любой клиентский кэш в начальном состоянии читать только вне гидрации:
`useSyncExternalStore(noop, () => true, () => false)` возвращает `false`, пока идёт гидрация.
Модульный флаг «уже гидрировались» не работает: его выставит первый компонент, а отложенные
границы гидрируются позже.

## `null` в кортеже внутренней раскладки ломает мобильную вёрстку компонента

`Textarea` держал `dir={['column', null, null]}` и `w={['100%', null, null]}`: `null` — пропуск
брейкпоинта, класс печатался только десктопу, и ниже 1024 подпись вставала слева от поля, а счётчик
уезжал за край экрана (горизонтальный скролл у проекта). У `Input` это чинили раньше, у соседей — нет.
Внутренняя раскладка компонента одна на всех ширинах — пишется полным кортежем `[x, x, x]`. Тот же
узор ещё стоит в `ChoiceButtons`, `Select`, `Skeleton`, `ToastProvider`, `Calendar`, `VideoPlayer`,
`RichTextarea` — чинить по мере встречи, сверяя вид на 375.
Одиночный `[x]` также не подходит: новый `DurationPicker` проходил типы самого кита,
но ломал сборку потребителя с `UiRules.strictTuple`. Все внутренние JSX-пропсы,
включая условные ветки вроде `fontWeight`, требуют трёх значений. Проверка — настоящий
`tsc --noEmit --incremental false` из потребителя со строгими кортежами.

## Аккордеон: пункт выше схлопнулся — нажатый заголовок уехал за экран

Одиночный режим закрывает открытый пункт, и если он выше нажатого, страница теряет его высоту: на
телефоне нажатый заголовок уезжал под шапку. Лечение — `holdPosition` в `AccordionItem`: пока в корне
аккордеона идут переходы (`getAnimations({ subtree: true })`), сдвиг заголовка гасится
`scrollBy({ behavior: 'instant' })` — без `instant` при `scroll-behavior: smooth` каждый кадр
перезапускал плавный перелёт. Колесо и касание удержание отменяют. Замер — только на видимой вкладке:
в фоне `requestAnimationFrame` стоит, и удержание выглядит сломанным, хотя работает.

## Видимая подпись поля должна быть связана с элементом ввода

`Input` и `Textarea` показывали `label` рядом с полем, но рендерили его обычным текстом. Сайт
добавлял `aria-label` вручную, а клик по подписи не ставил фокус. Лечение: нативный
`<label htmlFor={id}>` при уже существующем стабильном `id` поля; звёздочка обязательности
остаётся декоративной. Проверять по доступному имени и клику на подпись, а не по её видимости.
Для `RichTextarea` нативный `<label>` не подходит: `ContentEditable` — не нативное поле ввода.
Его видимая подпись получает `id`, редактор — `aria-labelledby` и `aria-required`.
Select с div-триггером следует тому же правилу: общий FieldFrame получает
ID подписи и команду фокуса вместо htmlFor. Явный aria-label сохраняет приоритет.
Проверка: Select/tests/render.test.ts и Select panel browser regression проверяют
связь подписи, настоящий клик/фокус и ref на триггер, а не на внешнюю оболочку.

## Общий хук движения подписывался в каждом примитиве — 2400 `matchMedia` на странице

`useSharedMotion` зовут `Flex`, `Box`, `Grid`, `Text`, `LexicalText`, а `useParallaxMotion` и
`usePerspective3dMotion` подписывались на `prefers-reduced-motion` и `pointer: coarse` эффектом с `[]` —
у каждого узла, даже без движения: на главной сайта фонда 2418 вызовов и 2370 слушателей. Наклон с
`follow: 'element'` вешал ещё и `pointermove` на окно у каждой карточки и мерил `getBoundingClientRect`
на каждое движение, хотя карточку уже вели её `onMouseMove`. Лечение: подписки — только при включённом
конфиге (`[enabled]`), окно — только для `follow: 'viewport'`. Стало 73 и 25. TBT при этом не сдвинулся
(≈770 мс на CPU ×4): время уходит на гидрацию клиентских примитивов, а не на подписки — мерить до/после,
а не верить счётчику. И не мерить при фоновой нагрузке: забытый `grep -r` по диску дал «TBT 1215».

## `import()` CSS рядом с `import()` JS — стили предзагружаются при гидрации

`Promise.all([import('pkg'), import('pkg/x.css')])` в хуке: сборщик вешает `<link rel="preload">` на CSS
ещё при гидрации, хотя JS ждёт наведения. Лечение — один модуль-загрузчик (`hooks/fancyboxLoader.ts`),
где CSS импортирован статически, и `import()` этого модуля: стили едут одним ленивым чанком с JS.

## Тип, который компонент кладёт в свою выборку, обязан быть доступен и вызывающему

**Симптом.** `MediaDropDown` отдавал тип в `MediaDropDownSelection.type`, а вызывающий тип выбирал
сам (`useState<MediaType>` + вкладка в поповере). Виды разошлись сразу: вкладка «Видео», а файл
`photo.png` — пилюля с картинкой, в модели видео, и предпросмотр открывает плеер с картинкой.

**Причина.** Два места решают одну задачу — «что это за файл» — и ни одно не знает про другое.

**Лечение.** Разбор вынесен чистыми функциями в `MediaDropDown/lib/media-type`
(`resolveMediaTypeFromFile`, `resolveMediaTypeFromUrl`) и вызывающий берёт тот же ответ, что и
компонент. Отдельным файлом — не для красоты: тест гоняет чистые функции, а модуль компонента тянет
в `node --test` scss и React.

**Правило.**

- **Значение, которое компонент выводит и кладёт в Selection-объект, вызывающий не считает заново.**
  Иначе первая же рассинхронизация видна только в предпросмотре.
- **`type` у ссылки выводить не из чего.** У адреса нет mime, остаётся расширение в имени, а без
  расширения единственный честный ответ — `file`: предпросмотр покажет имя, а не плеер. Умолчание
  надо назвать вслух (в JSDoc и в уроке), иначе «сломанный плеер» будет выглядеть багом.
- **Новый вид — новым пропом, а не заменой дефолта.** Библиотеку едят три проекта; `variant`
  со значением по умолчанию в прежнем поведении меняет вид только у того, кто его попросил.
  `value`/`onChange` при этом остаются: в новом виде они получают выведенный тип, и потребитель,
  который ими пользовался, продолжает ими пользоваться.
- **`bg` не задают пропом у кнопки с вариантом.** Утилита `bg_…` лежит в `ui.utilities`, а правила
  варианта — в `ui.components`; задав заливку пропом, выигрываете вы ТОЛЬКО в покое и молча
  гасите наведение и `disabled` того же варианта. Радиус и отступы так задавать можно: это
  лонгхенды, которых у варианта нет.

**Грабля в соседнем месте.** Рамку поповера пришлось оставить в модуле: панель продолжает пилюлю
(скругление сверху снято, верхняя линия не нужна), и это шорткат `border` с лонгхендом `border-top`
поверх него. Оба пришли бы классами-утилитами в одном слое, а кто из них окажется позже в
СГЕНЕРИРОВАННОМ файле — не решает ни специфичность, ни порядок вызовов: порядок классов в
`_utilities.scss` задаёт порядок обхода исходников. Четыре лонгхенда по сторонам работали бы, но
это четыре зашитых значения рамки вместо двух строк.

# Dropdown: клонирование триггера не должно терять обработчик вызывающего

`Dropdown` передавал в `cloneElement` собственный `onClick` и тем самым заменял обработчик кнопки,
которую передал вызывающий. Это ломало действия вроде аналитики или `preventDefault`.

**Лечение:** вызывать обработчик вызывающего первым, затем переключать панель, только если событие не
отменено и сам триггер не `disabled`. При добавлении обработчиков через `cloneElement` всегда сохранять
существующий callback и проверять отмену события.

## ModalProvider: побочные эффекты нельзя выполнять в updater состояния

`dismiss()` и `dismissById()` вызывали `onClose` и заводили таймер внутри функции `setStack`.
React вправе повторно вызвать updater: закрытие тогда повторяло callback и таймер, а callback
из сайта пытался обновить соседний компонент во время рендера. Закрытие теперь сначала отмечает
ID в отдельном наборе, обновляет стек чистым значением и вызывает `onClose` снаружи updater.
Повторный `dismiss()` до удаления окна ничего не делает.

`Modal` выставляет `aria-modal="true"`, поэтому Tab обязан оставаться внутри верхнего открытого
окна. Обработчик Tab перенесён из мобильного меню в сам `Modal`; он учитывает видимые остановки,
Shift+Tab, пустое окно и стек. Проверять клавиатурой вход, оба направления и возврат фокуса.

**Вход и запасной exit.** Provider ставил open через global double-rAF без владельца,
а повторная декларация с тем же `useId` могла получить поздний кадр старого узла.
Текущий opening generation отменяется при close/remove/reopen и в layout cleanup
провайдера; старый callback проверяет поколение прежде чем ставить второй кадр.
ModalSurface не заводит отдельный rAF для `entered`: Provider уже оставляет скрытый
кадр перед входом. Plain `present` fallback читает theme `motion.timing.normal` и
общий буфер, а ModalSurface заменяет его измеренным CSS exit. Проверять быстрый
unmount/remount того же declaration ID и длительность plain-node exit свыше 500 мс.

## Collapse внутри кнопки: размер слота и зазор должны уходить вместе

**Симптом.** Блочный `CollapseWrap` вокруг кнопки растягивал её на всю ширину строки. Для иконки
внутри кнопки он к тому же создавал недопустимую блочную обёртку, а обычный `gap` кнопки оставлял
бы пустое место после скрытия иконки.

**Причина.** Сворачивание целого блока и inline-слота используют один ход, но разную форму DOM.

**Лечение.** У `CollapseWrap` появился inline-вариант на `<span>` с `inline-grid`. `Button` использует
его для собственного сворачивания; `Icon` по умолчанию сворачивается по ширине. Когда иконка
исчезает внутри кнопки, зазор задаётся через `Icon collapse.gap`, а у `Button` — `gap={0}`.
Браузерная проба подтвердила уменьшение ширины кнопки на ширину иконки с зазором.

Когда вызывающему пришлось писать `Button gap={0}` и тот же зазор в `Icon collapse.gap`, API оказался
неудобным. Составной `DButtonIcon` теперь принимает `icon={{ name, collapse: { open } }}` и сам согласует зазор.
Для иконки слева общий движок умеет вести зазор с конца слота (`gapSide: 'end'`), для иконки справа —
с начала. Проверять оба направления: ширина кнопки должна уменьшиться на ширину глифа вместе с зазором.

## Проверка инструментов: дочерний test runner должен действительно запускать тесты

**Симптом.** Тест репортёра запускал намеренно упавший тест в отдельном Node, но получал код 0.

**Причина.** Родительский test runner передаёт `NODE_TEST_CONTEXT`; дочерний Node с `--test`
считает запуск рекурсивным и пропускает файлы. На Windows абсолютный путь репортёра также
нельзя передавать как ESM-спецификатор: требуется `file://` URL.

**Лечение.** Общий запуск независимых Node-процессов удаляет `NODE_TEST_CONTEXT` из копии env,
а путь репортёра переводится через `pathToFileURL`. Проверять реальным временным тестом:
ошибка утверждения должна дать код 1, имя, место и причину; успешные тесты не печатаются.

## DOM ref поля: обновлять при появлении и замене узла

**Симптом.** Внешний ref оставался `null` после загрузки или раскрытия поля; при замене
обычного Input на TimeField мог указывать на удалённый узел. Ошибка затрагивала также
Select и Textarea через общий `useFieldControl`.

**Причина.** `useImperativeHandle(ref, () => innerRef.current, [])` отдавал значение только
при монтировании. Позднее появление DOM-узла не запускало его повторно.

**Лечение.** Общий хук возвращает `fieldRef = useMergedRefs(innerRef, ref)`. Его подключают
к реальному контролу; Input объединяет его с ref измерения текста и передаёт тот же callback
в TimeField. Самописное присваивание с приведением к MutableRefObject больше не нужно.
При композиции ref'ов сохранять также функцию очистки callback-ref React 19, а не заменять
её вызовом с `null`.

**Проверка.** В браузере на временной странице потребителя проверены начально закрытые поля,
загрузка, повторное раскрытие, text ↔ time, смена внешнего ref, размонтирование и фокус.
Проверены объектные ref'ы, обычные callbacks и callbacks с очисткой; очистка при размонтировании
вызывалась один раз. Фокус и соответствие ref текущему DOM-узлу проверены на ширинах
320, 390, 768, 1024, 1440, 1920 и в альбомном режиме 740×380. Временная страница удалена;
этот браузерный прогон пока не входит в автоматический `ui:test`.

## Dropdown: якорь и состояние принадлежат своим уровням

**Симптом.** В Grid панель `matchTriggerWidth` получала ширину растянутой обёртки вместо
кнопки. При корневом collapse портальная панель могла пережить скрытый компонент.

**Причина.** Размер корня Dropdown не равен размеру его триггера; портал физически находится
вне сворачиваемого DOM-поддерева.

**Лечение.** Измерение и позиционирование используют DOM-корень триггера. Закрытый корневой
collapse блокирует открытие и сообщает владельцу состояния о закрытии панели. Режимы
open/onOpenChange и defaultOpen разделены типами; панель использует общий CollapseWrap.
Регрессии сравнивают ширину с кнопкой и проверяют скрытие панели при сворачивании корня.

**Fixture.** Постоянно открытый пример defaultOpen закрывался на чужой mousedown и сдвигал
страницу до mouseup. Такой пример теперь монтируется по отдельной команде своего сценария.

**Ширина поверхности.** Collapse grid не давал абсолютной панели вклад в intrinsic width:
оболочка совпадала с узким триггером, а содержимое выходило за неё. Панель теперь использует
max-content, измеряет координаты самого триггера даже в растянутом корне и ограничивает
портал с тем же viewportPadding, что у floating hook. Её единственная поверхность сжимается
горизонтально; структурное правило направления перекрывает существующее unlayered-правило
Collapse локальным селектором, не меняя вложенные collapse. Регрессия измеряет видимую
поверхность, включая w/maxW выше viewport, а не только ARIA-оболочку.

**Первый кадр портала.** Floating layout-effect мог измерить ещё скрытый keepMounted-контент,
а ResizeObserver исправлял положение только следующим кадром. Dropdown связывает
updatePosition с onTransition общего CollapseWrap: пересчёт после подготовки поверхности,
до отрисовки. Немедленная проверка alignment внутри прокрученной Modal воспроизводила сбой;
после исправления четыре повторения прошли без ожидания/ослабления утверждения теста.

## Modal: прокрутку удерживает слой, а не виджет

Эффект отдельного меню сбрасывал прежний overflow, освобождал страницу до окончания выхода
и конфликтовал с другими провайдерами. ModalProvider получает аренду общей блокировки
документа на срок жизни стека. Последний владелец восстанавливает исходные свойства и
приоритеты. Unit и browser проверки покрывают независимые провайдеры, unmount, закрывающийся
стек, !important, stable gutter и реальное колесо внутри окна без прокрутки страницы.

## Motion: выход запускает новый CSS clock

Смена animation-direction на reverse после завершённого входа сохраняет localTime: панель
сразу оказывалась в скрытом кадре. У выхода отдельное имя ui-reveal-out с тем же общим hidden
миксином. Modal сохраняет видимый базовый endpoint во время выхода, а legacy opacity снимает
только в режиме open motion. Проверять нужно середину выхода при обычном движении и освобождение
блокировки при reduced motion; проверка одного исчезнувшего DOM-узла этот сбой не ловит.

## Img: загрузка принадлежит своему источнику

Поздний load старой картинки снимал pending нового кадра: вуаль запускалась до его загрузки.
Swap хранит pendingIdentity, а каждый callback передаёт identity своего источника. Проверка
блокирует загрузку нового файла и отправляет load уходящему слою: ожидание должно остаться.
Быстрая смена сохраняет сторону начатого хода и затем показывает последний источник.

Локальные `/api/` не обязательно приватны: blanket `unoptimized` лишал публичную медиатеку
адаптивных размеров. Владелец проекта явно разрешает каталоги через `images.optimizeApi`,
без настройки приватное умолчание сохраняется; явный boolean Next-проп имеет приоритет.
Решение принимается для каждого кадра отдельно. У неоптимизированного `getImageProps`
нет `srcSet`: `<source>` получает `src`, иначе мобильный кадр молча заменяется десктопным.
Проверка: генерация → resolver, реальные Next srcSet, SSR Img/picture и preload ссылки
в `tools/tests/images.test.ts`; browser mock Next сам по себе оптимизацию не подтверждает.

## Cascade: декор и собственная анимация не занимают индекс

Load CSS считает nth-child только среди участников. data-reveal-skip — presence marker:
true ставит, undefined снимает; false у data-атрибута не означает отсутствие в DOM.
MutationObserver с attributes без subtree не видит изменения прямых детей. Подписка с subtree
фильтрует мутации по parentElement и не перезапускает каскад от вложенных изменений.

## Приёмка: ветку переключают после остановки тестового сервера

Даже fast-forward через временный checkout старого main меняет файлы, пока Vite читает их.
Браузерные проверки могут пройти, а поздний SSR-запрос получить ошибку загрузки модуля из
устаревшего графа. Сначала завершаем проверки, затем переключаем ветку; если это произошло,
повторяем затронутый сценарий на свежем сервере и общий запуск при стабильном рабочем дереве.

## Collapse: очередь команд и отмена

`show(); hide()` до коммита нельзя сравнивать только с последним отрисованным `open`:
вторая команда совпадает со старым состоянием, но должна заменить уже поставленную первую.
Храним одну ожидающую цель, прерываем прежнее ожидание и принимаем последнюю команду.
Promise завершается в layout-коммите, а не сразу по окончании WAAPI: ref поля должен быть готов.
При ручном cancel CSS уже стоит в целевом состоянии; снимаем клип/закрытый DOM без onEnd,
чтобы следующая команда не ждала исчезнувший переход. Browser-сценарии проверяют обе быстрые
разворотные пары, повтор, cancel, unmount, controlled отказ, SSR и reduced motion.
Команда может присоединиться к уже начатому controlled-переходу: результат отмены проверяет
текущий transition и принятую цель, а не только запрос, существовавший в момент старта.

`beforematch` тоже не обходит владельца: `flushSync` применяет принятое React-состояние до
браузерной прокрутки. Не ставим `data-open` вручную. При отказе восстанавливаем `hidden`
после того, как браузер снимет его; read-only компонент остаётся закрытым.

## JSX: фиксы не должны перекрывать друг друга

Правка атрибутов родителя перекрывает JSX внутри атрибута. Сначала применяем непересекающиеся
внутренние правки, затем повторяем разбор; иначе теряются дочерние изменения или смещаются позиции.
Типовые примеры с @ts-expect-error не форматируем: перенос пропса меняет строку диагностического
ожидания. Runtime правило исключает .typecheck / .type-test, компилятор продолжает их проверять.

## Непрерывный CSS-декор и параллакс вне экрана

IntersectionObserver у параллакса ограничивал запись стилей, но scroll-listener продолжал
читать getBoundingClientRect за экраном. Теперь видимость проверяется до чтения; возвращение
использует boundingClientRect самого observer. Из расчёта цели исключено собственное смещение,
чтобы повторный scroll без перемещения не менял цель. Сглаживание учитывает время кадра,
reduced motion сразу сбрасывает смещение, cleanup обнуляет отменённый RAF для StrictMode.
Браузерный тест проверяет стабильную цель, ноль offscreen-чтений и reset.

CSS infinite-анимация продолжала работать вне экрана. `useAnimationVisibility` ставит её
на паузу через локальную переменную play-state, без покадровых render. Button glow подключён
автоматически; общий hook доступен проектному декору. Проверяются выход, возвращение без
сброса текущего времени, visibilitychange документа и reduced motion.

### Геометрия наклона не читается на каждом движении указателя

**Симптом:** pointermove принудительно завершает style/layout и измеряет уже наклонённый
элемент. **Лечение:** исходный rect кэшируется на входе, инвалидируется при scroll,
resize, изменении размера и смене DOM-узла. ResizeObserver и слушатели очищаются.
Регрессия проверяет реальные pointer moves, число чтений, инвалидацию и видимый наклон.

### Скролл и счётчики: убрать повторную работу, сохранить движение

Даже чтение scrollY после записи стилей может принудительно завершать layout. Позиция
читается один раз на scroll-событие и передаётся подписчикам; размеры кэшируются с явной
инвалидацией. Счётчик не пересоздаёт текстовый узел, если округлённое значение прежнее.
Прямой параллакс отдаётся ViewTimeline через opt-in mode:'scroll', с прежним spring fallback.
Проверять реальный scroll, ручное прерывание, синхронную смену размера, композицию эффектов,
reduced motion и cleanup. Замер rAF под нагрузкой описывать как cadence, а не FPS вывода.

## Нативный цвет отменяет геометрию scrollbar — 2026-10-21

Симптом: в меню Chromium видна широкая полоса со стрелками вместо тонкой полосы кита.
Причина: унаследованный scrollbar-color страницы отключает WebKit-оформление Modal.
Лечение: ScrollArea, Modal и корневой viewport используют общий scrollbarProps и
одни стили; Chromium сбрасывает стандартный цвет в auto, Firefox сохраняет thin/auto.
Не добавляйте контейнер прокрутки вокруг страницы ради оформления: это меняет
владельца window scroll и нарушает SmoothScroll и sticky.

Тест промежуточной фазы закрытия Modal должен явно включать обычное движение.
Общий browser fixture использует reduced motion: окно может исчезнуть между двумя
последовательными проверками Playwright. Финальное снятие блокировки проверяют в обоих
режимах; наличие промежуточной фазы — при `reducedMotion: 'no-preference'`.
Для короткой анимации sampler запускают в странице **до** настоящего ввода:
`DurationPicker` успевал закончить движение между keypress, двумя locator-проверками
и первым измерением. MutationObserver + requestAnimationFrame сохраняют реальные
промежуточные transform/opacity независимо от задержек RPC; нельзя удлинять эффект
или ослаблять проверку ради теста. Регрессия: `duration-picker.spec.ts`, три повтора.
Если проверяется состав конечного WAAPI keyframe, перехвати `animate` конкретного
тестового узла до клика и сохрани `effect.getKeyframes()` возвращённой нативной
анимации: завершённого эффекта уже нет в позднем `getAnimations()` (`collapse-controls.spec.ts`).
Нативный вызов и продуктовые сроки сохраняются, перехват снимается сразу после записи;
скрытие и повторное раскрытие по-прежнему проверяются настоящим кликом.

Та же гонка проявилась в CI у fallback reveal: после ожидания `a0=done`
отдельный RPC уже видел `a1=done` вместо промежуточного `in`. MutationObserver,
установленный до прокрутки, сохраняет пары фаз; тест по-прежнему требует
реальное сочетание `done/in`, затем завершение обоих узлов. Сроки не изменены.
У React Profiler последнее событие может быть `nested-update`, а ограниченный
журнал способен вытеснить исходный `update`. Fixture отдельно сохраняет корневой
commit текущего действия; тест сбрасывает этот слот перед каждым настоящим кликом.
React вправе назвать commit из layout effect `nested-update`, поэтому наблюдение
принимает обе фазы обновления и не подменяет семантику React требованием `update`.
Проверка: оба browser-сценария по три повтора, затем shard 4/4.

Декларативная модалка теряет локальный provider → ReactNode перенесли в ветку общего
реестра → реестр хранит только слот/runtime, декларация создаёт портал из исходного
React-поддерева. Проверять consumer контекста между ModalProvider и Modal, вложенный
provider и обновление значения при открытом окне. Один портал сам по себе контексты
сохраняет; перенос узла к другому владельцу рендера — нет.

Закрытый вложенный Dropdown пропускает ArrowDown к родителю → родительская
навигация уводит фокус на соседнее поле. Триггер сам обрабатывает ArrowDown/ArrowUp,
открывает панель и фокусирует первый/последний элемент после монтирования Collapse.
Событие не всплывает; disabled не открывается, нативные поля сохраняют свои стрелки.
Проверять закрытое вложенное меню с порталом, `keepMounted: false` и соседним input.

## Hover и owner open используют разные источники состояния — 2026-10-23

Каталог проекта дублировал подложку, dismiss и CSS-выход, потому что Dropdown
предлагал только collapse. Добавлен OpenAnimate на существующую поверхность:
общий reveal рисует эффект, useOpenPresence сохраняет узел до exit, owner
сразу закрывает доступ через inert. При быстрой смене направления useReveal
снимает часы прежней CSS-анимации в layout cleanup и продолжает зеркальную
анимацию с дополнительной доли времени. Controlled-отказ закрыть панель
не должен переводить фокус обратно на trigger: возврат выполняется после
принятого изменения open. Регрессии — tools/browser/tests/dropdown-open.spec.ts.

Внешний клик проверяется относительно триггера и видимой поверхности, а не широкой
позиционирующей обёртки. Иначе пустое место рядом с узкой панелью считалось
внутренним и список не закрывался. DOM ref поверхности объединяется с motion/presence,
а React capture внутренних кликов ставится на неё: вложенные порталы остаются
внутренними без захвата пустой области обёртки. Пользовательский capture компонуется
без отмены внутренней отметки. Проверка: весь dropdown-open.spec.ts (8 сценариев),
включая клик рядом с поверхностью после вложенного портала; 14 связанных сценариев
Dropdown/Select подтверждают клавиатуру, фокус, Modal, вложенные порталы и controlled open.

Hover карточки нельзя определять по transform-узлу, если он — вложенное фото
или стрелка. Общий hover-transform выбирает self/parent/closest, учитывает
focus-within и очищает слушатели при смене ref. CSS владеет интерполяцией,
а reduced motion сохраняет resting transform, необходимый для увеличенного
растра. Регрессии — tools/browser/tests/hover-motion.spec.ts. В тесте Img размер
задаётся w/h, а состояние проверяется на .ui-img: data-testid относится к
внутреннему img. У Icon motion также может находиться на корневой обёртке.

Выпадающий список Select не нужно анимировать через корневой animate поля:
он относится к самому полю, а портальная панель живёт отдельно. Select передаёт
настройки panel.animate/collapse/r/offset общему Dropdown, сохраняя одного владельца
open, клавиатуру и ожидание exit. В проектной обёртке явные w/h не смешивают
с размерным пресетом, задающим свою высоту. Регрессия — dropdown-open.spec.ts:
раскрытие, быстрый разворот, выбор, Escape, радиус и reduced motion.

Геометрия Select и его фокусируемый узел — разные вещи: внутренний trigger уже поля
на padding и border. Панель привязывается через anchorRef к полному полю; фокус остаётся
на trigger. Клик на padding тоже открывает список. Поверхность списка использует
border-box, чтобы её border не увеличивал ширину в потребителе без глобального reset.

Scroll lock с `scrollbar-gutter: stable` нельзя компенсировать по изменению clientWidth:
в Chrome с тонкой полосой он меняется при overflow:hidden, хотя рамка html сохраняет
ширину. Измеряем getBoundingClientRect().width до и после блокировки. Регрессия проверяет
тонкую полосу, сохранение padding и его приоритета; unit отдельно моделирует расхождение.

### Точечное движение динамической сетки

Смена ключа content-swap у общего контейнера повторяет fade всех карточек и теряет

**Причина.** Длительность counter tuple читалась как миллисекунды, остальные API —
как секунды. TextSlide завершал JS swap по времени, отличному от CSS. Числа и easing
дублировались между стилями и контроллерами; чтение computed style в initial state
давало разные inline-длительности на сервере и при hydration.

**Лечение.** Public motion time — секунды или имя шкалы; адаптер переводит в ms один
раз. Генератор выпускает CSS и runtime из motion.timing/defaults/easing/inView/scroll.
Начальное состояние времени использует только runtime; layout effect уточняет его
по CSS на собственном узле. Общие easing presets хранят CSS и JS вместе, damping
нормализует кадр общими frameResponse/timeResponse, включая Marquee и scroll progress.
Скорость и время разгона Marquee принадлежат motion.defaults.marquee.
Все параметры SmoothScroll принадлежат только motion.scroll: дублирующий lerp в
defaults перекрывался сериализованным scroll.lerp. Регрессия генерирует непохожие
на базу значения и проверяет настоящие autoDurationMs, lerpStep и tweenPosition.
Lenis удалён, floating сохраняет native scroll capture.
ObserverMargin требует четыре стороны, legacy string и width-relative % сохранены.

**Проверка.** Unit проверяет единицы, кривые, генерацию и SSR fallback. Настоящий
renderToString → hydrateRoot с named time и другим CSS time не выдаёт ошибок и
обновляет clocks TextSlide/TextReveal/TextClip до CSS. Browser проверяет .6s tuple
counter, scoped 220ms slide, -10% bottom при разной ширине/высоте и reduced motion.

### Локальные иконки должны быть зарегистрированы до SSR

Icon имел синхронный реестр, но сборка потребителя его не наполняла: первый HTML
содержал пустые SVG, а глифы появлялись после клиентского fetch. Рабочий кэш повторного
визита скрывал проблему. tools/icons.ts теперь собирает public/icons при build/watch,
модуль одинаково инициализируется на сервере и клиенте. Регрессия рендерит реальные
иконки сгенерированного манифеста через renderToStaticMarkup, до эффектов и сети;
изменение, удаление и неверный SVG проверяются тестом генерации. Живой потребитель
проверяется с отключённым JS и холодным кешем: локальные SVG уже содержат рисунок.

### Активный пункт прокручиваемого меню должен оставаться видимым

Подсветка текущей секции не прокручивала viewport оглавления: на низком экране
активный пункт оставался за его границей. Публичный scrollTo получил container
и использует нативную прокрутку только заданного viewport с block nearest.
Провайдер документа не вызывается, команды разных контейнеров независимы;
следующая команда того же контейнера останавливает предыдущую. Unmount и timeout
завершают Promise, reduced motion сохраняет назначение.
Регрессия scroll.test.ts проверяет границу viewport, неподвижность документа,
видимую цель без лишнего движения, отмену и reduced motion. Живое оглавление
Diamonds4You на 1440×650 проверено по всем 11 секциям, включая обратный переход.

Для документа отдельный дефект обнаружился в передаче команды: `scrollTo` принимал
`block`, но провайдеру отдавал только `offset`, а SmoothScroll всегда выбирал начало.
Настройка теперь доходит до движка, который рассчитывает start/center/end/nearest
по текущей геометрии с прежними отступами и reduced motion. Регрессия
`components/SmoothScroll/engine.test.ts` проходит публичный вызов через настоящий
провайдер и движок. Изолированная текущая копия без передачи block воспроизводит
ошибку center (940 вместо 720); исправленный набор engine/scroll/smooth-scroll —
18 PASS. Проверены также анимация, явный offset и видимые/высокие цели; браузерная
приёмка нового выравнивания остаётся отдельной проверкой.

## Телефонная маска: каретка и подсказка не определяют данные

**Симптом.** В обычном Input type=tel Backspace в середине номера переносил каретку
с позиции 7 в конец. Подсказка sample из подчёркиваний давала maxLength=3.
**Причина.** Контролируемое форматирование меняло разделители без восстановления
логической позиции; потолок длины вычислялся форматированием sample как цифр.
**Исправление.** Маска отображает выделение по числу национальных цифр, Input
восстанавливает его после render через ownerWindow rAF с cleanup и проверкой ref/value.
Потолок берётся из ёмкости формата, sample может быть заполнителем без потери ввода.
**Проверка.** Pure regression и настоящий browser Backspace/Delete/range replacement,
Ctrl+V номера с 8, полный ввод/переполнение и очистка; CRM сохраняет E.164 через тот же Input.

## Потеря implicit touch capture не завершает захват родителя

**Симптом.** NativeCarousel начинал touch drag, но возвращался на первую позицию.
Mouse drag работал. **Причина.** После `setPointerCapture` на viewport браузер снимал
implicit capture с исходного дочернего элемента. Его `lostpointercapture` всплывал
к viewport и ошибочно завершал новый жест. **Исправление.** Обработчик завершает
жест только при `event.target === viewport`; pointercancel и потеря собственного
capture по-прежнему корректно завершают перетаскивание.
**Проверка.** Реальные CDP touchStart/move/end по дочернему тексту меняют позицию,
а следующий вертикальный touch-жест прокручивает документ без смены слайда;
`native-carousel.spec.ts` также проверяет mouse drag, отмену и unmount.

## Событие границ карусели не является событием смены слайда

**Симптом.** Пауза плееров, подписанная на `onNavigationStateChange`, могла пропускать
переход между двумя внутренними слайдами. **Причина.** begin/end/disabled не меняются
при таком переходе, поэтому callback границ закономерно не вызывается.
**Исправление.** У Swiper-адаптера добавлен аддитивный `onActiveIndexChange(index)`;
NativeCarousel предоставляет `onIndexChange` и отдельно приостанавливает native media
за видимой областью. Потребитель внешнего плеера подписывается на индекс.
**Проверка.** Четыре слайда старого адаптера публикуют все индексы в проходе
1→2→3→2→1→0; Native сохраняет единственный DOM video и ставит его на паузу.

## Повторная команда карусели продолжает физическое движение

**Симптом.** Второй next во время движения зацикленной ленты мог выбрать ближайший
экземпляр цели позади текущей позиции и заново разогнать движение с нулевой скорости.
**Исправление.** Направленные команды накапливают физическую цель отдельно от
абсолютного goTo; прерывание сохраняет текущую позицию и скорость для следующей кривой.
Смещения оригинальных слайдов обновляются только при пересечении границы слота.
**Проверка.** `native-carousel-rapid.spec.ts`: двойной next через 100/150/250 мс
на обычном участке и шве, серия из десяти команд, смена направления и reverse.
Проверяются непрерывная позиция, сохранение скорости и конечный индекс.
Тест со 100 слайдами проверяет отсутствие чтений layout во время кадров и не более
двух изменений смещений дочерних элементов при пересечении одной границы.

## Расширение Transition сохраняет идентичность общего контроллера

**Причина.** Обёртка `{ ...transition }` теряла связь с приватным реестром ядра;
отдельный переход работал, а together/sequence не управляли им корректно.
**Исправление.** Адаптер расширяет исходный объект, предварительно сохранив исходные
cancel/reverse для внутренних вызовов без рекурсии.
**Проверка.** Browser regression проверяет progress, отмену, завершение и композицию
реальных движений карусели через together и sequence.

## Нажатие не является начавшимся перетаскиванием

**Причина.** pointerDown сразу отменял анимацию: tap без drag оставлял ленту между
позициями. Отменённый touch-жест также мог подавлять следующий намеренный click.
**Исправление.** Прерывание и новая точка отсчёта наступают после порога осевого drag;
tap и поперечный жест не останавливают переход. Подавление click относится только
к завершённому drag и сбрасывается при следующем pointerDown, включая интерактивный узел.
**Проверка.** Browser regression проверяет tap/поперечный жест во время анимации
и настоящий CDP touchCancel с последующим первым нажатием ссылки.

## Каждая регистрация подписки имеет собственный cleanup

**Причина.** Хранение callback напрямую в Set объединяло два одинаковых
subscribePlayback(fn); cleanup первой регистрации удалял обе.
**Исправление.** Каждая регистрация получает независимую wrapper-функцию и
идемпотентный cleanup, как subscribeProgress.
**Проверка.** Unit дважды подписывает одну функцию, снимает подписки по отдельности
и проверяет доставку оставшейся регистрации без повторных отключений источника.

## Настраиваемое поведение карусели не прячется в движке

**Причина.** После добавления NativeCarousel времена инерции и пороги drag/wheel
оказались локальными числами, а общие boolean defaults — параметрами компонента;
проект не мог управлять ими единым ui.config.
**Исправление.** Boolean/axis defaults принадлежат motion.carousel, времена и пороги —
motion.defaults.carousel. Генератор валидирует и выпускает runtime/CSS, совместимый
fallback определён один раз; props переопределяют намерение экземпляра. Коэффициент
интеграла cubic ease-out и численные допуски остались частью формулы, не настройками.
**Проверка.** Generator tests проверяют иной config, старую форму и неверные значения;
runtime test проверяет scoped numeric/time, browser — реальную смену порога drag.

### Пример применения проверяется как потребительский код

Причина: пример Tooltip задавал только первый generic `useTooltip<HTMLButtonElement>`;
второй оставался `HTMLElement`, несовместимым с ref поверхности Tooltip `HTMLDivElement`.
Исправление: `useTooltip<HTMLButtonElement, HTMLDivElement>` без приведения и ослабления
публичного ref. Повторная проверка — компиляция самостоятельных TSX-блоков справочника
со строгими типами и реальными зависимостями. Кроме примеров сверяется описание пропсов:
общее слово «min/max» ошибочно обещало GridItem minW/minH, которых нет в GridItemProps;
договор перечисляет поддерживаемые w/h/maxW/maxH явно.

### Readonly поле не может применять seed при focus/blur

**Симптом.** `readOnly` Input с `autoComplete="off"` терял DOM-атрибут при фокусе;
readonly Input/Textarea с `seed` вызывали `onValueChange` на focus или blur.
**Причина.** Общая autofill-защёлка снимала `readonly`, а обработчики seed-коммитили
значения независимо от режима только для чтения. Событие change также могло быть
доставлено программно и обходило нативное ограничение браузера.
**Исправление.** Явный readonly исключает autofill unlock; seed и change-пути проверяют
readonly до записи/публикации модели. Проверка браузера находится в
`tools/browser/tests/regressions.spec.ts` и покрывает оба поля, фокус, попытку ввода и blur.

### Строковый RichText не должен обрезать вложенный список

**Симптом.** После sanitization nested `ul`/`ol` содержимое терялось либо попадало
в отдельный блок, а соседние пункты/текст после списка могли быть отсечены.
**Причина.** Нежадные regex останавливались на первом `</li>` и первом закрывающем
теге того же типа, не считая глубину вложенности.
**Исправление.** Parser балансирует одноимённые блоки и `li`, сохраняя HTML-разметку
внутри родительского пункта; чистый тест проверяет структуру, browser regression —
реальный DOM и следующий блок после списка (`legacy-html.test.ts`, `regressions.spec.ts`).

### Готовый Text.collapse не дублируется в оболочке поля

**Симптом.** При сборке FieldFeedback вокруг Text добавили Flex.collapse и
локальный retained state, хотя Text.collapse уже реализует оба механизма.
Владелец также указал на Fragment вместо принятой Flex-композиции.

**Причина.** Возможности используемого компонента не были проверены перед
добавлением собственного lifecycle. Старое устройство InputFeedback перенесли
в общую оболочку, не устранив повторение.

**Коррекция.** Collapse передан Text, локальная копия текста удалена; ошибка и
комментарий размещены в Flex. Зазор сообщения принадлежит collapse, зазор подписи
задаётся отдельно. Поведенческая проверка этой правки ещё выполняется.

**Повторная проверка.** Проверить отсутствие второго collapse/retained state в
FieldFeedback; в браузере пройти пустое сообщение, появление, смену, закрытие,
повторное открытие и error → comment. Измерить высоту и отступ, проверить
aria-describedby и reduced motion. Чтение JSX не заменяет эту проверку.

### Согласованная композиция не заменяется переносом сложности

**Симптом.** При рефакторинге Input владелец согласовал FieldFrame, InputControl,
InputActions, InputCalendar и InputOverflow с отдельными интерфейсами. Реализация
вместо этого передала frame/control/actions через spread и сохранила смешанные
обработчики и множество flags/refs внутри useInput и FieldFrame. Владелец отклонил
результат: короткий внешний компонент не соответствовал показанному эталону.

**Причина.** Длина файлов и разбиение стали подменой проверки обязанностей;
внутренний путь не был согласован целиком, а пример молча заменился другой схемой.

**Коррекция.** Реализация остановлена. В спецификации Input закреплена точная
согласованная композиция, отдельно обозначены непринятые внутренние договоры.
До возобновления требуется согласовать целые существенные реализации модели,
событий, режимов, проверок и представления. Runtime пока не исправлен.

**Повторная проверка.** Сопоставить Input.tsx с композицией спецификации; прочитать
все вызываемые части до ядра; для каждого интерфейса назвать владельца состояния
и зависимостей. Проверить отсутствие прежних смешанных обработчиков, спрятанных
за новым именем. Затем выполнить поведенческие проверки из страницы Input.
Зелёные тесты поведения сами по себе не подтверждают архитектурное соответствие.

При повторной реализации выявлено избыточное дробление: отдельные файлы небольших
календарных видов и независимые commit-последовательности числового, телефонного
и временного режимов. Коррекция: связанные виды собраны рядом; общий протокол
записи принадлежит Field.model, а режимы задают чистые преобразования. Проверка
сопоставляет всё дерево файлов и реальные зависимости, затем проверяет порядок
событий. Два выявленных drift защищаются сценариями: обычный ввод числа не
показывает новую ошибку до blur; телефонный callback сохраняет raw native event
при отдельно нормализованном значении модели. Перенос файла в core оправдан
общими consumers, а не уменьшением счётчика файлов Input.

### Портальный клик не является кликом строки поля

**Симптом.** После унификации Input поиск страны PhoneField закрывался при клике
в его поле: фокус возвращался в исходный телефон, и browser regression не мог
продолжить ввод.

**Причина.** В обработчике строки убрали проверку `currentTarget.contains(target)`.
React-событие портала всплывает по дереву компонентов, хотя его DOM находится вне строки.
Проверка Element и исключение action-слота сами по себе не задают DOM-границу.

**Коррекция.** Перед активацией строки проверяется принадлежность target её DOM.
Это сохраняет самостоятельный фокус портального поля, не меняя действий внутри строки.

**Повторная проверка.** Browser regression `PhoneField keeps picker aligned…`:
открыть страны, кликнуть поиск, ввести United States, выбрать страну, повторить
для Canada и убедиться, что исходный input сохранил DOM и значение. Проверка
обязательна и для портального Select/Calendar при изменении click/focus композиции.

### Черновик режима и native DOM восстанавливаются вместе

**Симптом.** После text → time → tel → text вернулся телефонный DOM-текст,
хотя словарь native draft сохранял прежний текст правильно.

**Причина.** При model → native на прежнем DOM-узле React перестаёт задавать value;
сохранённый React draft автоматически не записывается в uncontrolled input.

**Коррекция.** Общий Field восстанавливает native draft при смене канала/binding,
controlled → uncontrolled и замене DOM-узла. Обычный render не перезаписывает ввод.

**Повторная проверка.** Browser regression `independent uncontrolled drafts`:
реальной клавиатурой изменить text, time и tel, вернуться в каждый режим и проверить
его значение. Проверка storage без настоящего DOM не воспроизводит этот дефект.

## Собственные стили подкомпонента

Симптом: CalendarDays вынесен в отдельную папку, но импортирует Calendar.module.scss
родителя и не имеет собственного узнаваемого класса. Причина: представление
разделено без передачи владения стилями. Исправление по согласованному договору:
собственный Name.module.scss и именованный класс на существующем корне каждой
визуальной части, без новой обёртки. Проверка: нет импорта SCSS родителя/соседа,
сборка сохраняет класс, DOM показывает имя части. Правило распространяется на
всю DelbaUI; перенос исходных стилей выполняется при миграции соответствующей части.

## Фокус и завершение движения в документе владельца

Симптом: focusWhenReady сверял activeElement глобального document и создавал
observer в глобальном realm; readMotionMs и таймеры присутствия/смены содержимого
тоже читали глобальное окно. Для цели в другом документе это неверный владелец.
Исправление: документ и window берутся от реального DOM-узла; reduced-motion
принимает окно владельца, прежний вызов без аргументов сохраняет договор.
При переносе цели в другой документ ожидающая команда фокуса завершается отказом,
вместо наблюдения чужого документа. Проверка: focus.test.ts и motion.test.ts
проверяют фокус без глобального document, отсутствие view и вычисление длительности
через ownerDocument. Полный DOM lifecycle проверяется на финальном браузерном этапе.


## Нулевые значения оформления и булевы ARIA-строки

Симптом: Icon со strokeWidth={0} не передавал нулевую ширину, а Radio
с aria-invalid="false" получал error-state. Причина: проверка значения
по truthiness вместо его договора — число 0 ложно, строка "false" истинна.
Исправление: Icon.config проверяет отсутствие через undefined и нормализует
нулевые единицы, Radio явно исключает false и "false". Проверка:
Icon.config tests покрывают нули, единицы и null-брейкпоинты; Radio с
aria-invalid="false" включён в критерии финальной браузерной приёмки.


## Готовность SVG относится к конкретному источнику

Симптом по проверке пути: при смене URL useFetchedSvg до выполнения effect
возвращал разметку прежнего URL, а Icon уже вычислял новую идентичность swap.
Причина: асинхронный результат хранился без ключа источника. Исправление:
снимок помечен URL и режимом нормализации; на первом рендере нового источника
возвращается только его синхронный кеш либо пустое loading-состояние.
Повторная проверка в финальном браузерном прогоне: загруженная A → задержанная B
с change/swap; A сохраняется до готовности B, затем выводится B без подмены
старой разметки под новой идентичностью. Браузерное подтверждение этого прохода
выполняется в конце общей задачи.


## Изолированный вид редактора сохраняет публичную типографику

Симптом: LexicalTextarea, toolbar и VariableNode импортировали один SCSS; renderer
и редактор связывались прямым импортом модуля соседнего компонента.
Причина: стили документа, оболочки поля, команд и inline-токена имели разных владельцев,
но находились в одном модуле. Исправление: собственные именованные папки/SCSS для
editor/toolbar/button/token; читатель передаёт свои классы чистому renderer-helper.
Редактор использует существующий публичный richTextClasses договор типографики,
сохраняя совпадение опубликованного документа и редактируемого содержимого.
Проверка: component-anatomy и tsc; в итоговом браузере — форматирование, переменные,
selection и обе формы документа. Перенос файла сам по себе такую проверку не заменяет.

## Фокусная область не расширяет область pointer-dismiss

Симптом по ревью реализации: общий Dropdown добавлял focusRegions в pointer outsideRefs,
поэтому нажатие на пустую часть логической области поля считалось нажатием внутри popup.
Причина: один список использовали для разных договоров. Исправление: focusRegions
участвуют только в проверке ухода фокуса; pointer-inside — настоящий trigger/anchor
и окрашенная поверхность. Проверка: Keyboard policy tests подтверждают сохранение
клавиш содержимого; финальный браузер проверяет отдельные клики по полю, поверхности
и пустому месту между ними, включая вложенный портал.

## Внешний якорь сохраняет дизайн-единицы без парсинга CSS-выражений

Симптом по проверке пути: parseFloat(--rpx) не вычисляет calc/min, а внешний Dropdown
не имел probe исходного trigger-варианта. Причина: CSS-выражение ошибочно принималось
за готовое число пикселей. Исправление: оба варианта измеряют невидимый нулевой probe
с width:calc(offset * var(--rpx)); внешний вариант размещает его в уже существующей
панели. Проверка: компиляция SCSS и типы; окончательный браузер сравнивает зазор
при fluid scale, viewport resize и внутри темы Modal.

## Медиа clock и подписки принадлежат настоящему документу

Симптом: fullscreen и rAF читались из global document/window; повторный _attach не снимал
старые media listeners, а ratechange/emptied не обновляли snapshot. Причина: controller
связывал playback с глобальной средой вместо текущего media binding. Исправление:
ownerDocument медиа, detach перед новым attach, native ratechange/emptied и остановка
clock без subscribeTime-потребителей. Проверка: VideoPlayer/tests/useVideoPlayer.test.ts
подключает два media последовательно, проверяет отмену старого frame, отсутствие реакции
на старый volumechange, document-local fullscreen и emptied. Браузерный fullscreen и
реальный playback проверяются отдельно в финальной приёмке.

## Переподключение внешних контролов при замене карусели

Симптом по ревью: CarouselNav/Dots находили карусель один раз; MutationObserver отключался
после первого совпадения. Причина: найденный DOM-узел ошибочно считался постоянным.
Исправление: observer своего ownerDocument отслеживает childList/data-carousel-id и
переподключает snapshot подписку при замене узла; observer и события снимаются при unmount.
Проверка: type/architecture gate; финальный браузер заменяет карусель при сохранённой
внешней паре контролов и проверяет команды по новому экземпляру.

## Составной trigger сохраняет договор клонирующего Dropdown

Симптом: после выделения SelectTrigger его доступные props задавались только внутри
функции-компонента; Dropdown видел пустой aria-controls и подменял listboxId своим panelId.
Причина: cloneElement читает props элемента до исполнения дочернего компонента.
Исправление: Select передаёт accessibility на сам trigger-элемент; SelectTrigger
передаёт clone attrs, ref и составные события на существующий DOM-корень.
Проверка: Select/tests/render.test.ts проверяет country-listbox, listbox-haspopup,
expanded, видимую выбранную подпись и native hidden form input. Клавиатура и
реальный выбор дополнительно проверяются в финальном браузерном прогоне.

Внутренний аудит Select также нашёл вторую reset-подписку и неиспользуемый
string-state: useFieldControl вызывался только ради ID/ref/error, хотя выбор
уже владел собственным значением. Теперь Select хранит только selection/error
и одну подписку useFormReset, а подпись и feedback переиспользуют общих владельцев
FieldFrame/useFieldFeedback. При reuse hook проверяй весь его lifecycle, а не
только извлечённые поля. Reset/cancel reset и FormData подтверждаются настоящей
формой в браузере; SSR проверяет единственный ID ошибки и приоритет комментария.

## Общий Field сохраняет порядок публичной валидации

Симптом по ревью: перенос Textarea на Field менял validate → onValueChange на
обратный порядок и пропускал custom/length-проверку readonly на blur. Причина:
частный договор ошибочно приняли за универсальный порядок полей. Исправление:
чистая политика beforeNotify у Textarea и проверка readonly без записи значения.
Проверка: Textarea/tests/policy.test.ts покрывает длины, custom и readonly;
Textarea/tests/render.test.ts — реальные native props и aria-связи при SSR.
Порядок callbacks подтверждается финальным browser fixture, а не тестом одного флага.

## Scroll-host сохраняет блочный поток содержимого

Симптом финального браузерного прогона: четыре сценария Modal не прокручивались;
scrollHeight совпадал с clientHeight при длинном содержимом. Причина: замена
внутреннего block div на Flex column включила flex-shrink у детей и сжала spacer
вместо создания overflow. Исправление: существующий единственный scroll-host — Box
с блочным потоком; панель остаётся Flex. Дополнительный DOM не добавлен.
Проверка: Modal inner wheel, Select portal в scrolling Modal, nested Dropdown Escape
и declarative Modal с одним scroll owner должны реально менять scrollTop при wheel,
сохраняя scrollY страницы. Компактная композиция не оправдывает смену layout-семантики.

## Перенос SCSS сохраняет вложенность состояний

Симптом: после разделения Calendar на собственные стили частей все числа стали
белыми. Вложенный .dayText selected/active был ошибочно продублирован как базовый
селектор с !important. Sass компилировался, выбор даты работал, но цвет из props
перекрывался. Исправление: базовый Text задаёт семантический цвет, SCSS оставляет
белый только внутри selected/active; у базового текста остаётся transition.
Проверка: визуальный снимок и computed-color для обычной, недоступной, выбранной
и выходной даты (architecture-contracts.spec.ts). При переносе проверяй семантику
вложенных селекторов; одна компиляция Sass не подтверждает сохранение внешнего вида.

При том же переносе InputValue сначала получил повтор группового шрифта вместо
отдельного stacking-правила timeFieldMasked; восстановлены appearance/position/z-index.
Inline-ошибка также сохраняет прозрачность и color, и -webkit-text-fill-color,
включая autofill-селектор. Регрессия проверяет реальную частичную маску времени
и computed-color/fill до и после фокуса. Перенос по первому совпадению имени
селектора непригоден для вложенных и групповых SCSS-правил.

Нативный reset .field находился ниже .timeMask с той же специфичностью и перекрывал
цвет подсказки. Собственный модуль теперь явно задаёт вариант .field.timeMask;
проверяются color и text-fill маски по токену placeholder, а не только её наличие.

## Миграция animate включает публичный тип и парсер — 2026-11-02

Перевод JSX на объектный animate оставлял второй действующий договор в типах и
парсерах: Flex принимал animation/transitionKey, Text и LexicalText декодировали
tuple/responsive-входы, Icon/Img нормализовали строки, а reveal оставался отдельной
публичной дверью. Тесты, требовавшие совместимость этих входов, сохраняли legacy
после миграции потребителей. Исправление включает тип, decoder, экспорт, fixtures
и документацию вместе. Поддержка внутреннего CSS animation и normalized options
не означает сохранение старого API.

Проверка: src/hooks/tests/motion-api.types.ts компилирует отсутствие старых props и
строк/tuple в animate восьми примитивов; focused motion tests проверяют отказ
старым входам и прежние key/duration, очередь свопа, reduced motion и reveal CSS.
Нативные SSR/browser fixtures используют объектные load/inView/change/open.
Браузер выполняется отдельным общим gate после объединения изменений; unit/type
проверки не подтверждают фокус, вид и промежуточные кадры в браузере.

### Вложенный владелец skin

Генерация первого уровня пропускала skin внутреннего DButtonBase: собственный
SCSS больше не мог получить модификаторы, хотя defineSkin был корректен. Исправлено
единое рекурсивное обнаружение владельцев с игнорированием tests/generated и зависимостей.
Два skin в одной папке отвергаются вместо выбора первого файла ОС. Регрессии в
`tools/tests/skin.test.ts` создают настоящий вложенный fixture и проверяют states.

### Уведомления в StrictMode и до первого появления

Очистка всех timeout при replay эффекта оставляла первую карточку в состоянии
open без таймера. Подтверждено настоящим React StrictMode/useToastQueue на JSDOM:
child-effect создаёт уведомление на 15 мс, через 60 мс оно должно быть закрыто.
Очередь хранит deadline отдельно от timeout и восстанавливает оставшийся срок
при повторном setup; настоящий unmount запрещает новые команды старому API.

Карточка, вытесненная синхронной пачкой до первого commit, сразу закрыта и не
проходит exit-transition. Ожидание только onEnd не удаляло её из состояния.
ToastCard подтверждает удаление такого невошедшего элемента отдельным effect;
у уже вошедшего сохраняется полный exit. Browser regression проверяет остаток
очереди после двух пачек по семь уведомлений, отдельно — child-effect/StrictMode
и прямой toast после unmount. Эти сценарии входят в общий финальный browser gate.

### Замена контроллера во время drag освобождает захват

NativeCarousel пересоздаёт движок при смене controller без удаления DOM. Старый
destroy снимал listeners, но оставлял pointer capture и data-dragging=true:
после замены сохранялись grabbing и запрет выделения. Исправление обнуляет
собственный жест до releasePointerCapture и удаляет его DOM-состояние. Настоящий
mouse-drag regression в native-carousel.spec.ts сначала воспроизвёл зависшее
состояние, после исправления подтвердил освобождение захвата и работу next.

### Действие внутри внешнего label не активирует поле повторно

На сайте Input даты находится внутри внешнего label. Нажатие на padding
иконки попадало в её div-frame: затем браузер выполнял default action label
и посылал второй click связанному input. Календарь открывался и сразу закрывался.
Один лишь preventDefault на mousedown не отменяет default action последующего
click. InputActions отмечает всю существующую зону действий и отменяет её click
default через общий preserveFocus; обработчик поля не повторяет действие.
Регрессия использует настоящий внешний label и pointer click по padding:
до исправления календарь отсутствует, после работают открытие, Escape и повторный
toggle. Проверены также readonly/disabled, password и самостоятельный Calendar.
