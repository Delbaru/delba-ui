# Навигатор по справочнику библиотеки

Оглавление, а не правила. Читается, чтобы понять, КУДА идти; сами правила — в файлах ниже.

| Файл | Что внутри | Когда открывать |
|---|---|---|
| [`../AGENTS.md`](../AGENTS.md) | маршрутизация и обязательные границы | точка входа |
| [`development.md`](development.md) | подробный договор разработки | нужный раздел по задаче |
| [`../README.md`](../README.md) | подключение к проекту, договор темы, обновление сабмодуля | подключаю или обновляю библиотеку |
| [`authoring.md`](authoring.md) | как добавить компонент или проп: структура, TSX, SCSS, форма пропов | пишу или правлю компонент |
| [`core.md`](core.md) | что уже есть в ядре и обязано переиспользоваться | прежде чем писать помощник |
| [`checks.md`](checks.md) | приёмка: команды, что они ловят, чего НЕ ловят | перед словом «готово» |
| [`refactoring.md`](refactoring.md) | выборочный аудит и очередь рефакторинга; предложения, не действующие правила | планирую упрощение внутренней механики |
| [`lessons/authoring.md`](lessons/authoring.md) | грабли компонентов, типов и пропов | правлю то, что уже ломалось |
| [`lessons/styles.md`](lessons/styles.md) | грабли SCSS, слоёв и классов | трогаю стили |
| [`lessons/tooling.md`](lessons/tooling.md) | грабли генератора, сабмодуля, скриптов | трогаю оснастку |

**Разделение жёсткое, чтобы не было двух источников правды:**
`authoring.md` и `core.md` — как правильно · `lessons/` — на чём уже обжигались ·
`README.md` — как этим пользуются снаружи.

Искать по граблям: `grep -rn '<фраза>' docs/lessons/` — заголовки записей это правила, а не даты.
Читать файл уроков целиком не нужно.
