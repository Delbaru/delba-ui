# Аудит и план рефакторинга DelbaUI

Дата выборочного просмотра: 2026-10-26. Статус: предложения для изучения;
изменения API и реализация не приняты. Это очередь работ, а не новый договор кита.
Наблюдения основаны на чтении исходников, без браузерного прогона и измерений.

## Цель и приоритет

Уменьшать повторяемую механику и стоимость понимания, сохраняя обычную композицию
React. Число строк само по себе не критерий качества. Начать с одного небольшого
изменения и проверить его на нескольких реальных компонентах и потребителях.

Связанный план CMS ведётся в её собственном roadmap: раздел 35 «Аудит
рефакторинга». Репозитории самостоятельны; обновление кита не обновляет автоматически
архив UI, закреплённый в CMS.

## UI-R1. Единый договор композиции событий — первый кандидат

**Наблюдение.** В [Box](../src/components/Box/Box.tsx),
[Flex](../src/components/Flex/Flex.tsx), [Button](../src/components/Button/Button.tsx),
[Select](../src/components/Select/Select.tsx) и [Icon](../src/components/Icon/Icon.tsx)
повторяется соединение пользовательских обработчиков с обработчиками motion.
Порядок отличается: например, Box соединяет motion перед пользовательским
обработчиком, Icon для движения мыши — в обратном порядке. Button дополнительно
соединяет поведение ссылки, Icon — tooltip. Различие подтверждено чтением;
неправильность порядка и пользовательский баг не установлены.

**Предложение.** Сначала описать требуемый порядок и смысл `preventDefault`
для каждого сочетания. Затем вынести действительно одинаковую часть в небольшой
внутренний помощник поверх существующего
[composeEventHandlers](../src/core/composeEventHandlers.ts).
Не объединять различающиеся сценарии только ради одинаковой записи.

**Ожидаемый выигрыш.** Новое общее поведение подключается без копирования сборки
обработчиков; порядок вызовов становится проверяемым договором. Публичный API
и решения потребителя остаются видимыми.

**Риски.** Порядок событий может быть частью текущего поведения. Нельзя потерять
пользовательский обработчик, отмену действия, focus, ref или обработчики ссылки.

**Приёмка будущего изменения:**

- [ ] Составить матрицу порядка обработчиков по перечисленным компонентам.
- [ ] Проверить вызовы и отмену события тестами существующих сценариев.
- [ ] Удалить повторяющуюся механику у выбранных компонентов без изменения exports.
- [ ] Пройти gate кита и проверить hover/focus, ссылку, tooltip, клавиатуру и
  reduced motion в реальном потребителе по ui-verify.
- [ ] Если понадобится изменить наблюдаемое поведение, отдельно описать изменение
  договора и миграцию; не включать его незаметно в рефакторинг.

## Что брать из изученных материалов

- **Code Simplification:** сохранение поведения, ясные имена, локальный объём
  изменения и сравнение читаемости до/после. Применять как метод ревью.
- **Impeccable:** критерии визуальной проверки, типографики, композиции,
  адаптивности и состояний. Сверять с темой и правилами потребителя; установка
  нового навыка сама по себе не гарантирует качества.
- **Anatomy:** отдельный эксперимент для объясняющих схем и учебных материалов.
  Визуальная метафора не доказывает техническую точность модели.
- **Context7:** полезен для внешних библиотек; для собственного API DelbaUI
  источником истины остаются код и документация установленной версии.

CSS `@function`, View Transitions, замена движка диаграмм и Node debounce/throttle
не входят в этот рефакторинг. Их польза требует отдельного сценария и проверки
совместимости. Новый универсальный движок компонентов или анимаций не предлагается.
