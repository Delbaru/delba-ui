# Icon

Текущий договор, сверенный по исходнику; runtime-проверка отдельно.

## Назначение и применение

Inline SVG с общей геометрией, цветом, сменой иконки и необязательной ссылкой. Проектный DIcon задаёт словарь значков и стандартные размеры. Icon не заменяет кнопку действия: для неё нужна кнопка с доступным именем.

## Основной API

- `src` — URL SVG или SVG-компонент; `component` — готовый компонент. `name` ищет файл в `public/icons` **проекта**, а не во внутреннем каталоге кита.
- `w`, `h` задают геометрию SVG; `rootW`/`rootH` и `root*` — отдельную геометрию/стиль корня при необходимости.
- `color`, `fill`, `stroke`, `strokeWidth`, `rotate` задают оформление; источник SVG должен поддерживать выбранный способ окраски.
- `hover` выбирает другой источник при наведении; `animate={{ when: 'change', effect: 'swap', duration: 'fast' }}` — смена иконки. Сложные варианты — по типу IconProps.
- `href` включает ссылку; `tooltip` добавляет пояснение, но не заменяет доступное имя действия.

Публичный animate принимает только объект с явным when/effect. Строковые и
tuple-значения удалены; [миграция](../../../motion-migration.md) сохраняет фазы смены.

## Пример

```tsx
import { Icon } from '@delba/ui';

export function IconExample() {
  return <Icon src="/icons/arrow.svg" w={[24, 20, 24]} h={[24, 20, 24]}
    aria-hidden="true" />;
}
```

Предполагается реальный файл проекта `/icons/arrow.svg`. Значок декоративный; значимому значку задай имя, кнопке — имя самого действия.

## Устройство и владельцы

Icon.types.ts описывает публичный договор, Icon.config.ts — responsive CSS-переменные
и единицы измерения; нулевые rotate/strokeWidth не теряются при проверке наличия.
Icon.tsx собирает визуальный глиф/hover-слои, рамку, ссылку и collapse.
useIcon координирует отдельные источники и взаимодействия; Icon.model.ts содержит
чистые именованные операции геометрии и распределения native props между узлами.
useIconInteractions объединяет refs и события фокуса/tooltip/motion; React-хуки
не вызываются из чистой модели. Единственный `IconGlyph/IconGlyph.tsx` рендерит
компонентный SVG или безопасно разобранную разметку: тот же путь применяется
к обычному глифу и обоим hover-слоям. Загрузочный SVG сохраняет размеры;
объект innerHTML стабилен между рендерами с неизменившимся содержимым.
useFetchedSvg владеет загрузкой/кэшем и отличает SSR от клиентской гидрации.
Снимок привязан к URL и режиму нормализации: готовность прежнего SVG не
запускает swap для нового ещё не загруженного источника.

IconTooltip использует общий useTooltip и Tooltip, сохраняя собственный скин
и масштабирование содержимого. Повторных портала и fade-правил нет. Каждая
визуальная часть имеет свой SCSS и именованный маркер Icon/IconGlyph/IconTooltip;
существующие ui-icon* классы сохраняются. ref потребителя остаётся на SVG и
исключается из native props до их распределения: spread не может перезаписать
объединённый callback. Компонентный источник имеет приоритет над URL, поэтому
неиспользуемый URL не загружается и не определяет идентичность swap.

## Приёмка

Проверь реальный источник, пропорции, состояние ошибки загрузки и различие hover/touch. При интерактивном использовании проверь семантику, фокус и доступное имя. Смена SVG сохраняет корневой ref и корректно завершает движение при reduced motion.
При A → задержанная B swap держит A до готовности B; старый SVG не выдаётся
за готовый контент нового URL. Сценарий `Icon change swap keeps the loaded source
until the replacement SVG is ready` находится в [browser regressions](../../../../tools/browser/tests/regressions.spec.ts);
он запускается в финальном браузерном прогоне.
