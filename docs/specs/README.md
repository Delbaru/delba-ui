# Спецификации DelbaUI

Требования к результату и карта действующих договоров общей UI-библиотеки.
Исходный видеореференс и открытые вопросы обсуждения сохранены отдельно в
[specifications](../specifications.md); его черновой статус не меняет договоры ниже.
Этот каталог принадлежит DelbaUI и работает в отдельном клоне: продуктовые тексты,
тема и сценарии продаж остаются у потребителей. Версия договора соответствует
коммиту библиотеки; обновление документов не обновляет закреплённые копии у сайтов и CMS.

## Как пользоваться

Перед изменением прочитай [принципы](architecture/principles.md) и нужную тему.
Навык выбирается по задаче автоматически, без отдельного запроса пользователя.
Если задача пересекает репозитории, используй инструкции и навыки каждого владельца;
общую механику меняй здесь, интеграцию — у потребителя. Это не разрешает автоматически
менять закреплённые версии или выпускать библиотеку.
Проверь действующий договор по указанному справочнику и исходникам. Для нового
или меняющегося поведения создай предметную спецификацию по [шаблону](template.md),
если существующего договора недостаточно. Не создавай файл ради каждого исправления.
Неясные решения обозначай вопросами; не превращай предложение в принятое требование.
После реализации сверь критерии приёмки и обнови затронутый договор вместе с изменением.

## Статусы и источники

- **Базовый договор** — действующие правила, собранные здесь по темам; подробности
  остаются в справочнике. Не означает, что каждый существующий компонент проверен на соответствие.
- **Предложение** — желаемое изменение с открытыми решениями; реализации ещё не поручает.
- **Согласовано** — принятые требования предметного изменения; состояние кода фиксируется отдельно.
- **Заменено** — указана актуальная спецификация или миграция; старый договор не применяется молча.

Для предметной спецификации указывай статус, область, дату и основание согласования.
Реализацию и проверку записывай отдельно от статуса требований: состояние реализации,
дата и версия/коммит, выполненные проверки и их подтверждения, оставшиеся ограничения.
Согласованный договор может ещё не быть реализован; реализованный — не полностью проверен.
Справочник описывает текущие API и способы разработки; спецификация фиксирует
ожидаемый результат. Очередь предложений остаётся в [refactoring](../refactoring.md),
подтверждённые причины ошибок — в [lessons](../Library.md). Общий вход — [Library](../Library.md).
