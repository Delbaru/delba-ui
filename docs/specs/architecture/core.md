# Ядро и границы

Статус: базовый договор. Область: общая механика и зависимости DelbaUI.

Библиотека самостоятельна: импортов из приложения нет, потребитель использует
публичные exports. Подробные входы и интеграция — в [README](../../../README.md).
Размещение и инвентарь готовых механизмов — в [core](../../core.md),
структура репозитория — в [development](../../development.md).

Перед добавлением общего механизма найди существующего владельца и вызовы.
Layout, responsive, motion, refs и SCSS-помощники переиспользуются у владельца;
цвета, типографика и длительности читаются через договор темы.
Общая библиотека не выбирает за приложение продуктовые состояния compact/hide,
подписи кнопок или оформление заказа.

Читаемость проверяется через весь путь действия: вызывающий компонент показывает
намерение, а каждый внутренний хук и helper раскрывает собственную ответственность.
Выделяй отдельную причину изменения, не прячь последовательность за переименовывающей
обёрткой. Для наблюдателей ref — часть контракта: проверяй первый mount, замену DOM-узла,
cleanup и оба публичных способа привязки, если API принимает object ref и callback ref.

Улучшение ядра должно сохранять наблюдаемое поведение и объяснять конкретную
причину выделения общей части. При оптимизации нужны воспроизводимый сценарий
и сопоставимые измерения; предположение о скорости не считается результатом.
Проверка — [приёмка](../verification/acceptance.md). Очередь возможных изменений
в [refactoring](../../refactoring.md) не является действующим новым контрактом.
