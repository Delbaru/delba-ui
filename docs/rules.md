# Правила вёрстки на ките — для проекта

Общие для всех проектов на `@delba/ui`. Проект ссылается на этот файл из своего скилла вёрстки и
дописывает у себя только своё (палитру, D-компоненты, секции). Что помечено **[check]**, держит
`delba-ui check` с храповиком: старые места — долг в планке, новое не проходит.

---

## 1. Проп раньше SCSS

Перед каждой строкой в `.module.scss` — открыть `src/core/utilities/registry.ts`: есть проп — пишем
пропом. `bg`, `position`, `top/bottom/left/right` и `hide` — общие адаптивные пропсы коробки.
В модуле остаётся только непропсовое: `:hover`/`:focus-visible`, `overflow`,
псевдоэлементы, `z-index`, `transform`, `list-style`, `display: grid`, стили разметки внутри
`LexicalText`.

| Не так (SCSS)                                                         | Так (проп)                                           |
| --------------------------------------------------------------------- | ---------------------------------------------------- |
| `margin: 0; padding: 0;` **[check]**                                  | `m={[0, 0, 0]} p={[0, 0, 0]}`                        |
| `flex: none;` — не сжиматься **[check]**                              | `minW={[32, 24, 32]}` рядом с `w`                    |
| `color: var(--black)` у текста                                        | `<Text color="var(--black)">`                        |
| `--text: var(--black)` на секции, чтобы перекрасить детей **[check]** | `color` на каждом тексте; фон — `bg`                 |
| `li:last-child { border-bottom: … }`                                  | `borderB={i === all.length - 1 ? [...] : undefined}` |
| `width: 100%` у элемента колонки                                      | `w={['100%', '100%', '100%']}`                       |

## 2. Отступы — `gap` родителя

Расстояние между соседями задаёт родитель: `Flex dir="column" gap`. `mt`/`mb` у ребёнка **[check]**
остаются только на смещение декора (иконка-водяной знак), не на ритм блоков.

```tsx
// не так
<DSectionHead … />
<Grid mt={[48, 32, 40]}>…</Grid>

// так
<Flex dir={['column', 'column', 'column']} gap={[48, 32, 40]}>
    <DSectionHead … />
    <Grid>…</Grid>
</Flex>
```

## 3. Значения — литералом на месте вызова

Генератор утилит читает исходник и видит только литерал в пропе. Константа (`LINE`, `SIZES.md`) —
класс не сгенерируется, и это тихо **[check]**.

```tsx
borderT={['calc(var(--rpx) * 1) solid var(--line)', 'calc(var(--rpx) * 1) solid var(--line)', 'calc(var(--rpx) * 1) solid var(--line)']}
```

## 4. Корневой класс = имя компонента

Если `X.module.scss` содержит CSS-правила, он начинается с `.X { … }`, всё остальное вложено;
компонент вешает `className={styles.X}` на корень — секцию находят в DOM по имени **[check]**.
Файл без собственных правил может оставаться пустым каркасом: декоративный класс для прохождения
проверки не нужен.

## 5. Кортежи и сетка

Респонсив-проп — полный кортеж `[desktop, mobile, tablet]`; `null` — пропуск, а не «как desktop».
Числа кратны 4 **[check]**. `@media` в SCSS нет — кортежи, включая `hide={[desktop, mobile, tablet]}` **[check]**. Транзишн —
`var(--t-fast|normal|slow)` **[check]**.

## 6. Ссылка-карточка

Вся карточка — одна остановка Tab: ссылкой становится кнопка внутри (`Button href`), её `::after`
растянут на карточку (`inset: 0`, у карточки `position: relative`). Ссылка внутри ссылки и кнопка
внутри ссылки — невалидны. Кольцо фокуса рисует проект (`:has(.link:focus-visible)` на карточке).

## 7. Форматированный текст CMS

Текстовая часть блока (заголовок, лид, подзаголовки, абзацы) — одно поле `richtext`, рисуется
`LexicalText`. Цвет абзаца задаёт редактор; компонент — только цвет по умолчанию пропом `color`.

Проверки JSX различают responsive-геометрию компонента и его предметные данные:
options/accept/rows и нативные SVG-координаты не являются responsive-кортежами.
Нативный input допускается только как скрытый системный file picker с явными
type="file" и hidden=true, без spread, способного переопределить эти атрибуты.

SCSS-инфраструктура объявляет владельца комментарием @ui-style-owner theme-tokens
или @ui-style-owner native-reset в обычном глобальном stylesheet. Первый договор
разрешает media только для :root custom properties и штатных data-hide/data-order;
второй разрешает нулевые отступы только у body/html, заголовков и number-spinner.
Компонентные селекторы и .module.scss остаются под обычными правилами.
Корневой класс может уточнять настоящий тег: tr.QuickEditRow равнозначен
.QuickEditRow для идентификации владельца, при сохранении семантики таблицы.

Редкий проектный native-control owner объявляется @ui-native-control range:
компонент экспортируется под именем своего файла, импортирует собственный SCSS,
имеет одноимённый корневой маркер, а input сохраняет literal type=range, min/max,
value/onChange без spread. Это договор владельца специфичного ползунка,
а не разрешение нативных полей в экранах. Обычный input и любой другой type
этой декларацией не освобождаются от проверки.

Для условной ветки проверяется реальный motion owner: собственный animate
load/change/inView или collapse. Owner с animate change должен
иметь key, который зависит от условия; при load такой зависимый key ставится
самому корню для настоящего remount. InView, неизменяемый key и произвольный
анимированный предок с непрозрачным компонентом/порталом между ним и веткой
не заменяют motion смены дочерней ветки. Прозрачные Flex/Grid/Box/Text и нативные
layout-обёртки допускаются: реальный keyed owner удерживает их полное поддерево.
Поля с изменившимся контрактом не удерживаются ради exit со старыми callbacks.

Управляемый портальный компонент может объявить на именованной экспортируемой
функции `/** @ui-motion-owner open */`. Проверка разрешает импорт/алиас и реэкспорты,
находит настоящий корень DDialog → публичный Modal DelbaUI с явным open.
Один лишь тег, имя Dialog или произвольный проп open ничего не разрешает.
Потребитель передаёт open явно, без последующего переопределяющего spread;
условие сохранности данных не должно пересекаться с зависимостями open.
`asset && <Crop open={visible}/>` допускается при таком владельце;
`visible && <Crop open={visible}/>` остаётся нарушением: условный unmount лишает
настоящий портал собственного exit. Это контракт визуального владельца, не
обход проверки посредством дополнительной обёртки.
